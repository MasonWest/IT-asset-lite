## [v2.4.2] — 2026-10-13

**主题：修「在工位图上盘出的异常没有备注」—— 三条标记入口，只有一条不采集备注**

### 报障（用户原话）

> 「在盘点列表里选择异常，会弹出来一个标记异常，是可以写一些东西备注的，
>   
> 但是在工位图的盘点下，就只能点击缺失，缺少填备注的地方，最后导出 excel 自然也就没有备注」

### 先证伪一件事：导出是被冤枉的

导出链路**从头到尾都是好的** —— `EXPORT_COLUMNS` 里 `("note", "盘点备注")` 一直挂着，
  
`_export_rows` 也老实带了 `item.note`，接口 `InventoryMarkRequest.note` 也照收。
  
所以「导出没备注」不是导出的锅，是**最上游压根没人往那个字段写**。垃圾进垃圾出 —— 这次连垃圾都没进。

三条标记入口的备注能力：两条有、一条没有。

| 入口                                              | 采集备注         |
| ----------------------------------------------- | ------------ |
| 盘点列表 · 标记异常（`InventoryDetailView.markAbnormal`） | ✅ 弹框         |
| 资产详情页 · 盘点条（`InventoryContextBar.mark`）         | ✅ 弹框         |
| **工位图 · 点位侧栏（`MapStationPanel`）**               | ❌ 直接写库，没有输入口 |

### 真正断了两处（所以只补前端不够）

1. **前端不采集**：`MapStationPanel` 的「标记缺失」一行 `emit('mark', row.asset_id, 'abnormal')`
     
   就完事；`SpaceMapView.markAsset` 转发时也不带 `note`。
2. **后端不回显**：`MapInventoryAsset` **没有 `note` 字段**，`map_view()` 构造时也没带 ——
     
   即便从**列表**里填了备注，切到工位图照样看不见。这是**双向断点**，只修一处等于没修。

### 做了什么

- **后端**：`MapInventoryAsset` 加 `note`；`map_view()` 构造时带 `item.note`。
- **前端**：`MapStationPanel` 点击「标记异常」弹 `ElMessageBox.prompt` 采集备注
    
  （话术与列表页**逐字相同** —— 两处口径不许漂）；已经标过异常的会**带出上次备注**
    
  （重标是在改，不是从零写）；侧栏单独一行回显备注。`SpaceMapView.markAsset` 透传 `note`。
- **文案统一**：同一个 `result=abnormal`，地图原来叫「缺失」、列表/详情/导出/审计叫「异常」——
    
  现在**全叫「异常」**（只改用户可见文案，代码标识符一个字没动）。

### 验证（临时库，没碰 8080）

`IT_ASSET_DATA_DIR` 另起 8099 + 真实库副本（`.tmp/verify-note/`），跑三段：
  
① `map-view` 明细必须带 `note` 字段；② `POST mark` 带备注 → 落库；③ 再取 `map-view` → 备注**回显**。
  
三段全过（脚本 `.tmp/verify-note/verify_note_roundtrip.py`，抽样 1 台、写完还原）。

**⚠️ 改的是 `.py`：8080 上那个进程 9:18 起、比改动早 —— 必须重启后端才生效。** 前端 `dist` 已重新构建。

### 本次没动的（记账，别忘）

`markStation`（「一键把这个点位的设备全部标为已盘」）是**逐台循环调 mark** 的 ——
  
一个点位挂 N 台就是 N 个请求 + **N 条审计**，与本项目「一次批量操作 = 1 条审计」的既定口径相悖。
  
**这次没改**（会把「一个接口」变成「一个批量接口」，属于口径变更，不是修 bug），留待单独一轮。

## [v2.4.1] — 2026-10-12

**主题：修「新增点位死活加不上」—— 用户报障，两个按钮没冲突，是另外两条**

> 用户原话：「点新增工位，然后点击地图上需要新增的点位，但是工位死活新增不上去」
>   
> 「不管是不是在调整位置模式」「之前新增就很困难，有时点几下能出来，有时死活出不来」

### 报障人的猜测 vs 实测

**「新增」和「调整位置」两个按钮冲突 —— 没冲突。**
  
`adding` 和 `editMode` 是两个独立的 ref，按钮各调各的，
  
「新增」甚至**不需要先进「调整位置」**（宽屏按钮没有 `v-if="editMode"`，设计如此）。
  
实测：只点「新增」就能进新增态，`edit-on` 一直是 false。

### 真凶是两条（都是静默的）

1. **`.room` 把新增拦死了**（主因）。`onStageClick` 原来是
     
   `if (target.closest('.ws') || target.closest('.room')) return`。
     
   而 `.room` 是**纯装饰的房间矩形、没有任何点击行为** —— 排除它**没有任何好处**。
     
   坏处极大：**房间就是桌子所在的地方**。真实库 8 个房间盖住画布一大半，
     
   实测采样 40 个点，**20 个（正好一半）落在这类元素上，点下去静默无反应**。
2. **新增态下完全拖不动地图**。`canPan()` 里 `if (adding.value) return false` 一刀切，
     
   想加一个**视野外**的点位，得"退出新增 → 拖地图 → 再进新增 → 再点"四步。
     
   这是"新增很困难"的另一半原因。

### 修法

- **房间不再拦截新增**（删掉 `.room` 判断）。
- **新增态下空白处允许平移**，同时加 `movedDuringPan`（阈值 6px）——
    
  拖完松手时浏览器补发的那个 click 会被挡掉，**不会把点位误建在松手位置**。
    
  （实测：拖 200px 后 `tx` 变了、点位数量不变。）
- **点已有点位时给出明确提示**："这个位置已经有点位 Wxx 了。想加新的，请点空白处"。
    
  ⚠️ 提示放在 `select()` 里而不是 `onStageClick()` —— **`.ws` 上有 `@click.stop`，
    
  事件根本冒泡不上来**，第一版放错地方成了死代码（写完了才发现，靠探针抓到）。

### ⚠️ 最该记住的第三条：静默失败

上面两种情况下，用户点了三五次，**界面一个字反馈都没有** ——
  
他只能猜"是不是系统坏了"，然后来提 issue。**静默失败比功能缺失更伤**：
  
功能缺失至少有个空态告诉你"这儿没东西"，静默失败让人怀疑自己的操作。

### 新增验收

`e2e-add-station-regression-1012.js`（13 项，**会写数据，必须对临时库跑**）：
  
房间里能建上 / 两个模式互相独立 / 新增态能平移且不误建 / 点已有点位有提示 /
  
连点每次都稳。**13/13 通过。**

既有回归全绿：pinch 26 · canvas-guardrail 10 · map-ux 23 · banner 42（真实库）。

### 顺带：这次我自己踩的两个坑（都写进脚本注释了）

- `enterAdd()` 写成 toggle 语义却没判当前状态 → **重复调用把新增态关掉了**，
    
  D / E / F 三个场景测的其实是"非新增态"，报出两个假失败。
    
  （产品设计：`createStation` 成功后会自动退出新增态，避免用户接着乱点。）
- 读 ElMessage 用 `.slice(-1)` → 读到上一条还没消失的（duration 6000ms），
    
  改成"点击前数一下、点击后只取新出现的那条"。

## [v2.4.0] — 2026-10-08

**主题：补两处「静默分歧」（不改功能，只让两个数字不再互相矛盾）+ 给画布上护栏**

> 起因是用户问「抽手势逻辑、统派生函数值不值得做」。评估后**两件都不做**，但评估过程本身
>   
> 量出了两个**真实存在的静默分歧**，顺手补掉。

### ① 「什么算有人」前后端同口径（真 bug，只是现在还没显形）

- 后端 `assigned` 原用最朴素判据 `user_name.strip()`，前端 `hasOwner()` 则把
    
  「`/`」「`／`」算成**没归属**。项目早就认定「斜杠 = 没填」（真实库**资产**表有 15 台写的是 `/`），
    
  **但那个认定只在前端实现了**。
- **真库点位表此刻一个斜杠都没有**，所以两边数字一样、**差异是隐形的** ——
    
  这就是它能活到现在的原因。哪天往点位表填一个 `/`，后端就报「已分配 +1」而界面显示
    
  「未填使用人」，**同一页上两个数字打架且零报错**。
- 修法：新增 `backend/app/services/ownership.py` 作为判据唯一出处，
    
  `routers/workstations.py` 改走`ownership.count_assigned()`。
- **实测验证**：造含 `/` 和 `／` 的临时库 → 修复前 `assigned=3`，修复后 `= 1`。

### ② 后端 `empty` 改名 `without_asset`（一个命名陷阱）

- 接口的 `empty` 算的是「**一台设备都没挂**」（资产轴），
    
  而前端的「空闲点位」是 `total - assigned`（**没人用**，人员轴）——
    
  **两个都叫"空闲"，指的却是两件事**，同一页上对不上且不报错。
- 改成 `without_asset`，名字自带语义、不依赖读文档。
- ⚠️ **我自己先写错了一次**：对账断言按「界面空闲点位 == 无资产数」写，
    
  报出"界面 3 vs 算出 4"的假失败。**根因是断言拿两个维度互相对**，不是代码错。
    
  这跟①是同一类病，所以断言也一并改对了。

### ③ 画布护栏（替代「抽手势」）

- 缩放步长散在**三处**（模板 ±按钮 两处 + `onWheel` 一处），改的时候要改三处，
    
  漏掉一处**不报错**，只是"手感变了"，几个月后才发现。
- 固化成 `ZOOM_STEP_BUTTON = 1.15` / `ZOOM_STEP_WHEEL = 1.1`，
    
  并写明**两个值故意不同**（滚轮要连续滚动所以细腻、按钮一下就完所以要big一步）——
    
  **防止以后有人把它们"统一"成一个**，那是个合理但错误的行为。
- 新增 `e2e-canvas-guardrail-1008.js`（10 项）把这些常量**钉成契约**：
    
  改了值就红，并在信息里说明"你改了行为，是有意的吗"。
    
  **实测把 1.15 改成 1.3，立刻两条断言变红** —— 护栏真的会咬人。
- 顺带钉住一条早就该钉的：**视觉网格必须 == 吸附网格**（20px）。
    
  原型踩过"画的 20px、吸附按 4px，肉眼看不出对齐"这个坑。

### 明确不做：抽手势逻辑（评估结论）

| 量出来的数              |                                                                            |
| ------------------ | -------------------------------------------------------------------------- |
| `SpaceMapView.vue` | 2740 行（script 1380 / template 514 / style 843）                             |
| 纯手势函数              | **234 行**（12 个，占 script 17%）                                               |
| 其中带业务的             | `onStageClick` 直接调 `createStation`（写库+审计+撤销栈）、`canPan` 读 `adding/editMode` |

抽完 2740 → ~2600（**降 8.5%**），要动 26 项 CDP 真触摸验收守着的地方，
  
而 `onStageClick` 天生带业务 —— **传三个回调进去是假分离：文件分开了，风险一分没减**。
  
更关键的是**它解决不了真问题**：真问题是"改画布怕碰坏别的东西"，
  
抽文件之后改的**照样是同一套逻辑**，该怕的还是怕。**对症的是护栏。**

**什么情况下重开**：① 文件超 3500 行**且**新增功能要动手势；
  
② 要给手势写单元测试。**届时的正确解法是拆两个组件（地图渲染 / 侧栏与弹窗），不是抽 composable** ——
  
真正难拆的是"模板里有 10 个弹窗和侧栏"，不是那 234 行动作。

### 新增验收

| 脚本                                  | 项数     | 说明                                                                                                                           |
| ----------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `backend/check_ownership_parity.py` | **15** | **读前端 `format.ts` 真实源码**抠出 `NO_USER_MARKS` 字面量逐条比对 + 六个边界用例 + `count_assigned` 自校验。**只在浏览器里复刻前端逻辑等于自己抄自己** —— 抄错了两边一起错，测试照样绿 |
| `e2e-ownership-endtoend-1008.js`    | **7**  | 接口 `assigned` == 前端逐点数 + 界面顶栏三个数字一致 + `without_asset` 与「空闲点位」是两个维度                                                           |
| `e2e-canvas-guardrail-1008.js`      | **10** | 缩放上下限与两个步长、滚轮锚点漂移 ≤0.5px、视觉网格 == 吸附网格                                                                                        |

**15 + 7 + 10 全部通过。** 既有回归在真实库 8080 上全绿：
  
map-ux 23/23 · banner 42/42 · pinch 26/26 · station-relation 31/31。

### 踩到

- **Node 里 `execFileSync` 调 python撞 `spawnSync EBUSY -4082`** ——
    
  本机 `python.exe` 正被跑着的服务实例占着，起不来第二个进程
    
  （和 npm/esbuild 首次安装同一个坑）。**对策：拆成两个脚本，各用各的主场** ——
    
  Python 那边只跑纯函数比对（不占端口），浏览器那边只看接口结果。
- **回归一度红 4 条**（`下拉项数 >= 60` / `无点位卡数值`），根因是打到 8098 的
    
  **4 个测试点位临时库**而不是真实库。**换回8080 全绿。** 不是代码问题。

## [v2.3.1] — 2026-10-07

**主题：降「改动税」—— 文档同步从"每次必做"改成"按分级，该动的才动"**

> 起因是一句很实在的话：「只有红线改动才更新 CS」。
>   
> 照字面执行会连带砍掉**决策表**（那 74 条恰恰是最该留的），
>   
> 所以做成了**分级**而不是一刀切。

### 问题（实测，不是推演）

- 加一个点位关系层要动 **8 个文件**，其中一半是文档 —— **一半力气花在"把已发生的事再抄一遍"**，
    
  而下次改动 90% 不会碰它，抄了也不看。
- **手抄的数字必然不同步，而且会训练人忽略 CS**：
    
  第十节验收表写「banner 43 项通过」，脚本改过之后实际是 42；
    
  表里写「62 个点位」，库里已经 63 个（用户自己加的）。
    
  **CS 一旦不可信就真的废了** —— 这是比"文档长"严重得多的问题。

### 改了什么

- **第十节「验收」不再记"多少项通过"**。数字由脚本自己打印，CS 只记**口径**
    
  （怎么跑 / 哪些只读 / 哪些必须对临时库 / 两条断言纪律）。
    
  原来那 90 行"每个脚本当初怎么写的"整段收敛（它属于 CHANGELOG 的历史段落）。
- **第八节「功能现状」明确划界**：只记"现在有什么能力"，**不记"怎么演进过来的"**。
    
  判据写成一句可执行的：**"半年后有人接手时，这条还有用吗？"**
    
  带日期的叙述（"2026-09-30 加了…"）和实测数字（"62 个点位"）一律不进本节。
- **第十四节「维护约定」改成 14.1 分级表**，默认值&#x662F;**"什么都不用改"**：
    
  内部重构 / 调样式 / 改措辞 / 修不改变行为的 bug → **三份文档都不动**。
- **新增 14.2「三份文档各管什么」**（含越界警示），把"别把实施历史写进 CS"变成明文。
- **README 加「第一次用：10 分钟做出你的第一张图」**（第 0 节，在「现在有什么」之前），
    
  并在「快速开始」顶部留了跳转。起因是今天实测 clone 走查：新人读完快速开始装好服务，
    
  打开地图看到空白**还是不知道下一步** —— 那一节在第 480 行。

### 不砍（明确写下来免得以后误伤）

- **决策表不砍，只让它变慢**：加决策的判据是"这条口径将来会被别人误读吗"。

**主题：修「全新 clone 的人」的前 10 分钟 —— 别再往新用户库里塞本项目办公室的平面图**

### 问题（都是实测，不是推演）

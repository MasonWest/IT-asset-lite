# 空间地图 · 实现

> 用户视角怎么用看 [../user/map.md](../user/map.md)。
> 这一篇记"为什么是这么实现的"，包含 2026-09/10 的实测数字 —— 它们不是进度报告，
> 是"当时为什么选这个值"的证据，改参数前值得看。

### 关系核对与迁移的边界（v2.5.0，三条动作别混）

| 你要做的事 | 走哪里 | 改什么 |
| --- | --- | --- |
| 把桌子挪个位置 | 地图页「编辑点位」`PATCH /api/workstations/layout` | `x` / `y`（纯排版） |
| 这台设备换到别的点位 | 点位侧栏资产行的「换点位」→ `POST /api/relocations/*` `mode=assets` | `assets.workstation_id` |
| 整个点位连人带设备搬走 | 关系核对卡片右上「迁移」→ 同上 `mode=station` | 上面一项 + 点位使用人（+ 可选退役源点位） |

**这三条在界面上必须看起来就不一样**，理由见决策 67（混放"草稿型"与"立即生效型"出过真实事故）。

### 资产空间地图

页面：顶栏「空间地图」→ `/map`。数据侧只加了 **1 张表 + 1 个列**：`workstations` 表 + `assets.workstation_id`。
「资产在哪个点位」只存 `assets.workstation_id` 一处（决策 31），点位表里**不存资产列表**。

| 能力 | 接口 / 命令 |
| --- | --- |
| 地图渲染（含画布尺寸与派生 `asset_count`） | `GET /api/workstations` |
| 侧栏真实资产 | `GET /api/workstations/{id}/assets` |
| 改人 / 改编码 / 改备注 | `PATCH /api/workstations/{id}` |
| 拖动后批量保存坐标（**一次 = 1 条审计**） | `PATCH /api/workstations/layout` |
| 新增（编码后端生成）/ 删除（软删除 + 资产保护） | `POST` / `DELETE /api/workstations/{id}` |
| 资产挂到点位 / 从点位摘下来 | `POST` / `DELETE /api/workstations/{id}/assets[/{asset_id}]` |
| 地图盘点视图（五种点位状态，一次拿全图） | `GET /api/inventory/tasks/{id}/map-view` |
| 灌入点位 JSON（默认干跑，`--yes` 才写） | `python backend/import_workstations.py` |
| 按使用人自动关联资产到点位（默认干跑，只处理干净的 1+1） | `python backend/link_workstations.py` |

**点位 JSON 的格式**是 `asset-space-map/workstations@1`（`schema` / `canvas` / `summary` / `workstations`）。
导入以 **`code`** 为匹配键 upsert（不是 x/y，不是 seq），结果分四桶
（新增 / 更新 / 无变化 / 失败）。**JSON 里的 `assets` 字段被显式忽略** ——
那是原型侧的假数据，和真实 `assets` 表没有任何可对齐的键（决策 38）。

**地图盘点的五种点位状态**：`checked` / `abnormal` / `pending` 由该点位下**属于本次任务**的
资产 `result` 聚合而来（优先级 异常 > 待盘 > 已盘）；`empty`（这位置没有资产）与
`not_in_scope`（有资产但不在本次范围）是视图层专有的两种中性态，**不写进 `inventory_items`**
（决策 35）。**进度分母用资产数**（`task.total`），不是点位数（决策 37）。

**首次落地的两步命令**（顺序不能反）：

```
python backend\import_workstations.py --yes   # 1. 灌入 JSON 里的全部点位（含使用人）
python backend\link_workstations.py           # 2. 干跑，看哪些能自动关联
python backend\link_workstations.py --yes     # 3. 确认后写入
```

第 2、3 步只处理**「一个人恰好 1 台主机 + 1 台显示器」**的组合（判据是
`device_type.category`，不是类型名 —— 名字可改，category 不会）。
0 台或 ≥2 台一律**跳过**并在干跑里列出原因，留给人工处理：
硬关联出来的错数据比没有数据更难发现。符合条件的大约是一半（v2.9.10 实测 41 人 / 82 台）；其余是"一人 2 主机 2 显示器"、
"只有一体机或笔记本"，以及"有设备但没有点位"的人，都要人工处理。

**这个脚本只写「资产 → 点位」的归属，不碰主机↔显示器配对关系** ——
那是 `link_monitors.py` 和配对页的职责，两件事分开，谁出错都查得清。

**必须有任务选择器**：地图顶部要显示「当前盘点《XXX》」，即使只有一个进行中任务也显示。
**前端页面**（`frontend/src/views/SpaceMapView.vue`，侧栏在 `components/MapStationPanel.vue`，
纯函数在 `utils/workstationMap.ts`）：

- 视觉与交互沿用原型 V19（用户验收过的版本）：点位卡片、三层拖拽吸附、对齐参考线、
  缩放平移、空格临时平移、ESC/Delete 键盘。**渲染仍用原生 DOM**，几十个节点不需要 Canvas。
- **localStorage 已彻底移除**：改人 / 改坐标 / 增删全部落库，刷新和换浏览器看到的都是同一份数据。
- **拖动攒批保存**：拖动只改本地，点「保存布局」一次性提交，**一次 = 1 条审计**。
- 搜索覆盖四维：点位编码 / 使用人（**含拼音首字母**）/ 资产编号+品牌 / 轻资产品类；
  结果是**下方浮层**（Teleport 到 body，不受工具条 `overflow-x` 裁切），
  分组显示命中点位与「不在图上」（人持有的配件、未挂点位资产）。
  搜不到时全部变暗并在图例提示，不会让人以为搜索坏了。
- 侧栏资产用 `asset_code` 当主标识（真实库 SN 全空），品牌型号做了去重。
理由见决策 36 —— 不显示的话，两个任务重叠时地图会给出一个用户没问过的任务的答案。

**地图页满铺（2026-09-30）**：`/map` 是**唯一不受 `main.page-host` 阅读宽度约束的页面**。
全局容器那套 `max-width: 1240px` + `padding: 24px 20px 64px` 是为台账/列表这类一屏文字定的，
套到地图上会同时犯三个错 —— 把整页截成 1200px 的居中窄块（左右各空 360px）、上下留白、
总高超出视口而多出一条纵向滚动条。表现就是"接进系统后地图整体缩小了"。
修法是路由 `meta.flush` → `main.page-host.page-host--flush { max-width: none; padding: 0 }`；
**选择器写两个类**是为了压过窄屏媒体查询里的 `main.page-host`，否则手机上又缩回去。
地图自身高度是 `calc(100vh - var(--appbar-h))`，与抬头 HUD 严丝合缝、页面不再滚动。

**与原型 V19 的尺寸差是结构性的，不是 bug**：集成后比原型矮 52px
（全局 HUD 56 + 地图工具条 60 vs 原型单条顶栏 64），画布自适应缩放因此小 5.3%
（1920×1080 下 `0.700` vs `0.739`）。这是"保留全局抬头"的必然代价；
要抹平只能动抬头或把地图工具条并进去。

**地图的手机端适配 + 拖动平移（2026-09-30）**：断点 `≤900px`，
CSS 的媒体查询与 JS 里的 `compact`（`window.matchMedia('(max-width: 900px)')`）
**必须用同一个数** —— 一个管"画布怎么摆"、一个管"抽屉长什么样"，
对不上就会出现"按桌面布局算的居中 + 按手机布局画的抽屉"叠在一起。

- **根因**：侧栏是 `width: 390px; flex: none` 的常驻右栏，而手机屏本身才 390px 宽 ——
  画布被挤成 **0 宽度**（实测 `viewport.w = 0`），整屏都是"选择一个点位"那句空态文案。
  改成**浮在画布上的底部抽屉**（`position: absolute`，不参与 flex 分配，
  高度 `min(58%, 460px)`），且**未选中点位时整个 `.sheet-host` 不渲染** ——
  手机点进地图第一眼最该看到的就是地图。
  宽屏下 `.sheet-host { display: contents }`，包装层不生成盒子，原布局一字未动。
- **点点位时保缩放、只平移**（`centerOnStation`），把选中的点位挪到抽屉上方那块可见区中央。
  **刻意不调 `fit()`**：抽屉占掉近六成高度，按剩余高度重算会把缩放压到 0.2 上下、
  点位缩成十几像素、手指点不中，恰好把"按点位盘点"这件事做废。
  `fit()`（适应）本身会扣掉抽屉挡住的那截（`sheetInset()`），它给的是"屏幕上真能看见的都装下"。
- **拖动平移是这次补上的**：这块之前**是空的** —— `spacePressed` 只换了个 `cursor: grab`，
  没有任何移动画布的代码。"按住空格临时平移"在那之前只是一句注释。
  宽屏下画布 fit 得下、看不出问题；手机上一缩到 0.36 就非常致命：只能看、不能移。
  用 pointer 事件（鼠标 / 触摸 / 触控笔一套代码）+ `.viewport { touch-action: none }`
  （不写这条，手指一划页面先开始滚，收不到 `pointermove`）；
  落在点位上时让给原有的「搬点位 / 选中」逻辑，按住空格则强制平移。
  当时的短板是**只能一根手指**：捏不动，放大只能点工具条的 ±（一次 15%）。
- 地图工具条与盘点条从**横向滚动**改成**换行全部铺开**：手机上"要横滑才找得到的按钮"等于不存在。
  图例从右下挪到左上（右下是抽屉的位置）；`.map-page` 高度补 `100dvh` 回退，
  避免移动浏览器地址栏出现时裁掉画布下沿。
- 断点、抽屉比例、图例位置这几个数**都是实测出来的**（390×844：画布视口 390×614、
  scale 0.365、抽屉占地图区 58.0%），不是拍的。

**手机端"上方固定区"的第二轮压缩（2026-09-30，用户反馈"上面占了 50%、没法操作"）**：
"换行铺开"这个方向是对的（不藏按钮），但**代价当时没量**。实测 `.map-topbar` 折了
**4 行 / 178px**：统计独占一行 → 搜索独占一行 → 6 个编辑按钮自己折 2 行 → 缩放再一行。
一进盘点模式再加 128px 的盘点条 → **固定不动的合计 358px / 844px = 42.4%**，画布只剩 486px。

三刀砍下来 —— 非盘点 27.3% → **17.7%**，盘点 42.4% → **20.1%**，画布 486 → **674px（+39%）**：

| 刀 | 做法 | 效果 |
| --- | --- | --- |
| 统计不再独占一行 | `.stats` 改 `width: auto`、`.stat` 转 `flex-direction: row`（"62 总点位"横排小字 ~110px），搜索与它同行 | 省 1 行 |
| 编辑按钮收进「更多」 | `.tb-extra { display: none }` + `.tb-more` 下拉；宽屏相反，靠 `display: contents` 让包装层不生成盒子（决策 54） | 省 2 行 |
| 盘点态隐藏全局统计 | `.map-page.audit-on .stats { display: none }`（决策 56） | 工具条 2 行 → **1 行 53px** |

盘点条本身 128 → 65px：省掉「当前盘点」四个字（右边的选择器本身就是说明）、
**手机上删掉进度条**（进度已由「已盘 x/y（z%）」那句文字完整表达，留着就必须 `width:100%`
再占一行）、六个 chips 挤进一行。长文案走 `.wide-only` / `.compact-only` 由 CSS 切（决策 55）。

**双指捏合缩放（2026-09-30，用户反馈"手机端没法丝滑双指缩放，只能一个指头移动"）**：
上一轮把平移补上了，但**多指这件事根本没进过设计** —— 每个 `pointerdown` 都被当成同一根手指，
第二根指头落下只是把平移起点覆盖掉，两指同向滑变成缓慢平移、反向滑则原地打架，
表现就是"捏不动"。现在 `onPanStart/Move/End` 维护一张 **`pointers: Map<pointerId, {x, y, pan}>`**：

| 手指数 | 行为 |
| --- | --- |
| 1 | 平移（准入规则不变：空白处 / 按住空格；落在点位上的拖拽仍归「搬点位」） |
| 2 | **捏合缩放**，锚点 = 两指中点；间距不变就是一普通平移 |
| ≥3 | 不参与计算；抬起一根后**重取基准**，不让中点瞬移 |

- 锚点算法：`beginPinch()` 记下起手中点对应的**画布坐标** `ax/ay`，
  `applyPinch()` 每一帧 `tx = 中点x - ax * scale`、`ty = 中点y - ay * scale` ——
  手指中点下面那块地图"长"在手指上。**必须换算到画布坐标**，直接拿屏幕坐标算会变成"以画布原点缩放"。
- 手势期间 `getBoundingClientRect()` **缓存一次**（`pinch.ox/oy`）：每帧取会强制重排，60fps 下会很涩。
- 缩放钳在 `MIN_SCALE 0.2` / `MAX_SCALE 3.0`（原先 0.2/3 散在 `fit`/`zoomBy`/`onWheel` 三处，
  这次收成常量 —— 加双指时差点只改其中一处）。`fit()` 仍额外夹 1.5，保持"适应"的原手感。
- 抬手细节：只抬一根时清 `pinch.active` 并**用剩下那根手指重建平移基准**，否则会按旧基准跳一下；
  松开的那根若起手落在点位上，也照样能接着拖（决策 58）。
- ⛔ 别给 `.viewport` 加 `user-select: none`（决策 59）。
- **工具条上的 `−` / `＋` / `适应` 一个都不能少**：手势有学习成本，按钮是零成本兜底；
  而且部分真机浏览器有系统级双指手势（缩放页面 / 截屏），会把手势抢走。
- 验收脚本 `e2e-map-pinch-0930.js`（26 项）用 **CDP `Input.dispatchTouchEvent` 发真触摸**，
  不是合成 `PointerEvent` —— 见第十节。

⚠️ chips 用 `flex-wrap: wrap` 而**不是**"横向滚动"——滚动会把最后一片裁掉，
用户根本不知道还有「范围外」这个筛选项（第一版实测就是这样，截图里最后一片被切了一半）。
图例也跟着瘦一圈（`padding: 5px 9px`、字号 10.5px、提示句独占一行），55px 装下五个色块 + 提示。

**地图搜索（v2.9.5）**：**一个框、四个维度** —— 点位编码 / 点位使用人（拼音）/ 资产编号 + 品牌 /
轻资产品类（名称 · 品牌 · 规格）。命中**不自动居中**，点结果行才 `centerOnStation()` 并打开详情。
结果是 `Teleport` 到 body 的浮层（`.map-topbar` 是 `overflow-x: auto`，绝对定位的子元素会被裁），
分两组：图上的点位（带"为什么命中"的标记）与「不在图上」（人持有的配件、未挂点位资产，给跳转出口）。
索引**第一次聚焦搜索框才拉**（`/api/assets?page_size=1000` + `/api/light/holdings?page_size=200`），
迁移应用后自动失效重拉。口径与取舍见决策 93–96。

**地图上的轻资产位置（v2.9.6）**：**没有角标、没有图层开关** —— 点位上的一个件数说明不了
"是什么、在哪一条"，而轻资产是混合池（同一品类可以在主机 / 人手上 / 库存里）。
要看位置用两处：搜索（四维浮层，人持有的候选位置一并标出）与点位侧栏的**四组明细**
（`direct` / `via_assets` / `stock` / `via_users`，最后一组是**推断**，不参与总量）。
口径见第五节「轻资产」。

### 平面图编辑器（v1.2.0 引入，v1.2.1 收口：批量生成搬出）

**为什么加**：点位的增删改拖在 2026-09-30 就做完了，但**建筑图元（地台 / 走道 / 房间 / 墙体 /
前厅 / 入口）是写死在 `SpaceMapView.vue` 模板里的 19 行 inline style**。用户没法自己画一张
属于自己办公室的底图。所以这一步的实质是**把平面图从"模板常量"变成"数据"** ——
编辑能力是数据化的自然结果，不是另起一套系统。

**数据侧只加 1 张表 + 1 个列**：`floor_maps` 表 + `workstations.floor_map_id`。

| 能力 | 接口 / 命令 |
| --- | --- |
| 平面图列表（**恒为一张**） | `GET /api/floor-maps` |
| 默认那张图（地图页与编辑器都读它） | `GET /api/floor-maps/default` |
| 单张 / 保存整张（含乐观锁 409） | `GET` / `PUT /api/floor-maps/{id}` |
| 批量生成点位（行列排布，**一次 = 1 条审计**） | `POST /api/workstations/bulk` |
| 地图页入口 | 顶栏「编辑底图」（手机端在「更多」下拉里） |
| 批量生成入口（**不在编辑器里**，见决策 67） | 地图页「编辑点位」模式顶栏「批量生成」｜手机端在「更多」下拉里 |

**图元为什么存 JSON 不建表**（决策 60）：图元没有任何东西引用它们，永远是"整张图一起编辑一起
保存" → 存成一个 JSON 文档就够。建 `map_shapes` 表只会换来一堆"删图元要先删关联"的伪问题。
点位不一样（有 `code` 唯一约束、被 `assets.workstation_id` 引用、能单独增删改）→ 必须留表。
**两者形态不同不是不一致**。对照 `asset_events.detail` 也是用 Text 不用 JSON 列。

**`layout` 文档的格式**：`{"schema_version": 1, "shapes": [...]}`。
`schema_version` 是 **JSON 文档最基本的可演进性**，不是为未来扩展（半年后 `room` 字段一变，
库里那些 layout 就分不清是哪一版）。**读取的唯一入口是 `parse_layout`**
（后端 `services/floor_map_layout.py` / 前端 `utils/floorMap.ts`），
**任何组件都不许直接 `json.loads` / `JSON.parse`** —— 那会出现"地图画出来了、编辑器打开是空的"
这种两边理解不一致的鬼故事。

**八种图元 kind**：`zone`（地台）/ `corr`（走道）/ `corrtext`（走道文字）/ `room`（房间）/
`wall`（**竖**墙，宽固定 6）/ `divider`（**横**分隔条，高固定 6）/ `lobby`（前厅）/ `entry`（大楼入口）。
⚠️ **竖墙与横条是两个 kind，不是同一个加参数** —— 原型里把横条写成了 `.wall-v` + inline `width`
来覆盖，2026-09-30 接入时就是被这个歧义吃掉了 2 条隔断（同批还漏了大楼入口与桌椅，
桌椅按决策 61 明确不做）。

**编辑器是独立页 `/map/editor`**（决策 62）：`/map` 手机端顶部固定区只剩 17.7%，塞不下绘图
工具条；而且"编辑"与"看地图"该是两件事，避免只想看看时误触改坐标。三栏布局
（图元列表 / 画布 / 属性面板），画布与 `/map` 共用同一套坐标语义（960×1320，网格 20）。

**编辑器的三条交互口径**：
- **图元删除不弹确认**（决策 63）—— 它在内存文档里，`Ctrl+Z` 能回来。
  通用原则是**可撤销的操作不拦，不可撤销的才拦**。只有「离开页面且有未保存改动」与
  「删除整张平面图」才确认。
- **撤销栈存快照不存 diff**（深度 50）。拖拽中间帧**不进栈**（`mutateWithoutHistory`），
  松手才补一步（`commitSnapshot`）—— 否则拖一次图元会灌满 50 步，撤销变成"一格一格退"。
- **编码真相在后端**：批量生成面板显示的「将生成 W63~W86」**只是给用户的预期**，
  真正分配在后端事务里查全量 `code` 兜底。撞号就 **409 报错，绝不静默跳号** ——
  因为有「已删点位编码不释放」这条既定设计，跳号会让用户拿到的号段和实际落库的对不上。
- **批量生成不在这里**（决策 67）。它 2026-10-02 落地时曾放在编辑器左栏，同日按用户意见搬走 ——
  理由见下面「批量生成点位」一节。

**批量生成点位**（用户评价为"整个项目最有价值的功能"）：画一片区域 → 总数 / 起点 / 行列间距 /
每行几个 / 朝向 → 一次生成 N 个。朝向支持 `alternate`（**整排交替**：第 0 行朝下、第 1 行朝上），
因为现实里面对面的工位是「一排 4 个、桌子对拼、对面再 4 个」—— **整排同向**才成立。
`cols=4` + `count=8` 应当一次得到一组 4+4。

⚠️ 2026-10-27 改：原先是按**列**交替（`col % 2`），生成出来同一排里左朝下、右朝上，像锯齿 ——
那种朝向在任何真实排布里都不存在。规则现在唯一实现在 `services/station_layout.py::resolve_bulk_facing`，
`tests/test_workstations.py` 锁着它（按行交替、单行全朝下、四行交替、字面量与 `models.Facing` 对齐）。
**必须有 `POST /bulk` 独立接口**：循环调 24 次 `POST /api/workstations` 会往审计页灌 24 条
「新增点位」，把真正的资产操作淹掉（全系统口径是"一次批量操作 = 1 条审计"）。

⚠️ **它在地图页 `/map` 的「编辑点位」模式里，不在 `/map/editor`**（决策 67）。
**底图是底图，点位是点位** —— 这句话是本节的判别标准：

| | `/map/editor` 做的事 | `/map`「编辑点位」做的事 |
| --- | --- | --- |
| 对象 | 建筑图元（地台 / 墙 / 房间…） | 点位 |
| 写库时机 | **进草稿**，`PUT /floor-maps/{id}` 才落库 | 每个动作**立刻落库** |
| 撤销 | `Ctrl+Z`（内存快照栈） | 软删除 / 内联「撤销」按钮 |
| 手感 | 画完一起保存 | 所见即所得 |

问题的本质是**同一个按钮在两种模式下语义相反**：编辑器里"新增图元"是"加进草稿、不保存就没了"，
而"批量生成点位"是"立刻 `POST` 进库"。用户按前者的心理预期点了后者 → 24 个点位当场落库，
退出编辑器时因为"草稿"概念根本不会提示保存 → 事故（2026-10-02 真实发生，已回滚）。
把点位相关的一切收进点位自己的家（`/map` 的编辑点位模式），这个歧义从根上消失。

**三层手滑防护**（因为它是全系统唯一"点一下就写 24 行"的地方）：
1. **面板常驻警示条** —— 打开面板第一眼就写着"此操作会立刻写入数据库"，不是弹窗，不会被无视；
2. **点「生成」弹 `ElMessageBox.confirm`** —— 取消就是不写，一次请求都不发；
3. **生成后面板留「撤销生成」** —— 走软删除逐个删掉刚生成的点位，确认后执行。

**撤销 ≠ 批量操作，所以审计是 N 条不是 1 条**：撤销生成 6 个 = **6 条 `workstation_delete`**。
审计口径（决策 67）是"一次用户操作 = 1 条审计"，生成是 1 次操作（1 条 `workstation_create`），
撤销是 N 次独立删除（用户点的是"撤销"，系统做的是逐个软删），不做成"批量删除"接口。
**撤销走软删除、编码不释放** —— 和"已删点位编码不释放"这条既定口径一致，
撤销后重建会拿到**新的**号段，不会复用刚删掉的号（别把它当 bug）。

**单图心智模型（红线，决策 64）**：后端可以有 `map` 概念，**前端只能有"这一张图"的概念**。
`GET /api/floor-maps` 返回的 list 里**永远只有一张**；选择器 / `?map=` / `maps[]` / 多图 Tab
一律禁止。`floor_map_id` 是**关系预留，不是功能预留** —— 最怕滑向
「数据库支持多图 / API 半支持多图 / 前端假装支持多图 / 业务其实单图」那种复杂度凭空增加的状态。
将来真要做多图，改的是接口那一层（放开 list、加 `?map=`），数据不用迁。

**E0 铁律：只做数据化，不许顺手改视觉**。这一步的全部意义就是"图元从模板搬进数据库"，
颜色 / 样式 / 字体 / 点位卡 / 移动端一律不动。验收靠 `e2e-floor-legacy-parity.js`
（22 项）**逐图元逐字段对账**原型几何 vs `floor_maps.layout` ——
**"看起来画得一样"不算验收**（吃过亏：上次接入时肉眼验收，少了 5 个图元），
"每个图元坐标一致"才算。

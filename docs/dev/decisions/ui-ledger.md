# 决策 · 台账与筛选界面

| # | 决策（短标题） | 理由 / 代价 |
| --- | --- | --- |
| 16 | 台账筛选里**设备类型 / 位置 / 使用人是多选，唯独「状态」保持单选** | 上面那排统计卡点一下就切状态，卡片本身是单选语义；状态也做成多选，就会出现"卡片只高亮一个、筛选框里却勾着三个"的错位 |
| 17 | 配对页主机列有「只看没配显示器的」，但待配对池的**「挂到主机」下拉故意不受它影响** | 那个下拉是用来挑**目标主机**的。跟着开关一起收窄的话，正想把显示器挂到某台主机上，却在下拉里找不到它 —— 两个控件的筛选范围必须各自独立 |
| 18 | 「加显示器」弹窗**默认只列还没配出去的显示器**，要看已挂机的得先勾一个开关 | 满屏「当前挂在 XXX（换绑）」是噪音，挑一台新显示器得先做完排除法。但换绑能力没有丢，勾一下就回来 —— 是"默认收起"不是"藏起来" |
| 20 | 套装聚合在**后端**做（`GET /api/assets/grouped`），不是前端把当前页数据分组 | 列表是 `id desc` + 每页 24 条，主机和它的显示器行距中位数 **85 行**、最大 131 行，47 条配对**没有一条落在同一页**。前端只拿得到当前页，连对手方都看不见 —— 勾了等于没聚合。分页必须在聚合**之后**做 |
| 21 | 组内**任意一台**命中筛选，整组完整出现（配套设备会被"顺带"带进结果） | 反例更糟：筛「类型 = 主机」时若只显示主机，那 47 台主机会显示成「未配显示器」—— 那是**错误信息**，比多显示一台更坏。代价是结果里混进了没被筛选命中的设备，所以页面上用一行蓝底提示把「命中 60 台 / 额外带出 47 台 / 共覆盖 107 台」写清楚，不让人以为筛选坏了 |
| 22 | 套装行**不参与**标签与导出逻辑，一律展开成设备明细 | 勾一个套装行打印，出的是 **2 张**标签不是 1 张；不说清楚用户会以为打少了。所以按钮文案直接带张数（「标签（2 张）」「打印选中标签（2 张）」）。导出更彻底：`currentQuery()` 里根本没有聚合开关，导出永远出明细，也永远不会因为列表换了视图而变样 |
| 23 | 台账页把两种模式统一成**同一种「行」结构**渲染 | 明细模式下每台设备被包成一个只有自己的 `single` 行。看着多一层包装，但换来模板 / 选中 / 标签 / 分页只有一套代码 —— 否则「两种视图 × 两种模式」= 4 套渲染分支，改一处必漏三处 |
| 24 | 配对页默认隐藏使用人写 `/` 的主机（半角 `/` 和全角 `／` 都认），**但这条规则只作用于主机侧，显示器一律不筛** | 项目没有人员字典表，使用人是自由文本，「这台不归谁」就被写成了斜杠 —— 15 台里 13 台是主机，全在公共区域，而且**一台显示器都没配**，正好全堆进「只看没配显示器的」：19 台里占 13 台，想挑出真正要配的那几台得先做一遍排除法。显示器不一样：写 `/` 的显示器照样得有人给它找主机去挂，藏起来只会漏配。两侧语义不同，就不该套同一条规则 |
| 25 | 过滤生效时，「只看没配显示器的（N）」的 N **在前端按过滤后的集合重算**，不用后端 `stats` | 后端那些数字是**全库统计**，不受页面开关影响。直接拿它当标签数字，会出现「写着 19 台、勾上只看得到 6 台」这种对不上的情况。同一页上「主机（54）」也是这个道理 —— 统计卡是全局事实，列表是筛选结果，两者本来就不该相等，但**相邻的两个控件不能互相矛盾** |
| 26 | 台账的筛选 / 页码 / 视图**全部写在 URL query 上**，子页面的「返回」回到 **`?back=` 里记的那个地址**，而不是 `router.back()` | 列表页没有 `keep-alive`，状态只存组件内 `ref` 的话，点进详情再出来就全没了 —— 这是"返回后筛选丢失"的根因。不用 `router.back()` 是因为**扫码直接打开详情页的人，浏览器历史里没有列表页**，`back()` 会把他弹出应用；写在 URL 里则刷新、收藏、发链接、前进后退全都成立。写 URL 必须用 `router.replace`，用 `push` 会把「每翻一页 / 每敲一个字」都塞进历史，用户点几次返回还在列表里打转。`?back=` 只认**单个** `/` 开头的站内路径，挡掉 `//evil.com` 这类协议相对地址（见 `useBackNav.ts` 注释）。**地址栏会长成 `?back=/?status=idle%26view=table` —— 那是对的，别去"修"**：vue-router 4 的 `encodeQueryValue()` 刻意不转义 `/` 与 `?`，只转义 `&`，所以参数边界依然唯一、`URLSearchParams` 也解得干干净净（`route.query.back` 就是 `/?status=idle&view=table`）。写测试时**用 URL API 解，别拿字符串 split**。**配对管理页同样把三项筛选（关键字 / 隐藏使用人「/」的主机 / 只看没配显示器的）写进 URL**（`keyword` / `hide_no_user=0` / `unpaired=1`，只在偏离默认值时写）；它的 back **不用 `useBackNav()` 而自己 `router.resolve` 现算** —— `syncUrl` 的 replace 是异步的，刚敲完字就点设备时 `route.fullPath` 会少带一个条件 |
| 27 | 「使用人」下拉的拼音别名**在前端现算**（`utils/pinyin.ts` + pinyin-pro），**不在库里存 `name_initials` / `name_pinyin` 列** | 拼音唯一的用途是**筛这个下拉的候选**，而候选（`GET /api/meta/filters` 的 `users`）已经整份在浏览器里（不是分页）；选中之后发给后端的仍然是**真名** `user_name=林晓薇` —— 所以把拼音存进库里属于**只写不读**。真往 `assets` 上加列还有三个具体代价：① 142 资产只有 57 个非空取值（**重复 2.46 倍**，一个人最多占 6 台），改一个人的读音要 UPDATE 全表；② 那张表里「公用」16 行、「/」15 行、「会议室一 / 二」5 行**根本不是人名**，会被填上没有意义的值；③ 写入路径有四条（新建 / 编辑 / 领用 / 导入），每条都得同步维护这个派生列，漏一条就漂移。另一个"零依赖"的常见偷懒方案（拿 GB2312 一级字库边界表推首字母）实测在真实数据上**漏 9/57** —— 一级字库只收 3755 字，「婷 嘉 鑫 媛 婧 茗 娓 昝」全在二级字库。也**不需要防抖**：57 项本地字符串比较是微秒级，加 1s 延迟只会让人打字时觉得卡。多音字只把**首字**按姓氏读音（`mode:'surname'` + `surname:'head'`），两种一刀切写法都错：不开姓氏模式则「单 / 查 / 仇 / 曾 / 解 / 区」当姓时全错，整串开则姓氏读音串到第二个字（「陈思远」读成 wang-jiayue、首字母 lxw ≠ csy）。**将来真遇到算错的生僻姓**，正确落点是一张 `user_alias(user_name PK, initials, pinyin)`（一个人一行、只存例外），而不是往 `assets` 上加列 |
| 28 | 「使用人」下拉里，库里没有的名字渲染成**候选的最后一项**，于是**回车 = 选第一个真实候选**（不再用 `allow-create`） | 原来开着 `allow-create`，而 Element Plus 把创建项**固定插在候选列表最前面**，配合 `default-first-option`（默认高亮第一项）→ **打一个拼音首字母回车，存进去的人名就是那串字母**；打「林晓」回车存成「林晓」而不是「林晓薇」。这个坑在拼音筛选之前就存在（只要打的是"半个名字"就会踩到），而拼音首字母让它被踩得频繁得多 —— 打首字母本来就是为了选那个人。改成自渲染创建项并排在最后之后，四条路径都对：`dnn`→员工A、`林晓`→员工B、`李雷`→李雷（新建）、`zzz`→zzz（新建）。**"新建项跑到了列表末尾"看着像位置不对，是故意的**。顺带：EP 的 `reserve-keyword` 默认为 `true`（选完把关键字留在框里、让人用同一个词连挑几个），必须显式关掉；且它清的是自己的 `inputValue`、**不回调 `filter-method`** —— 我们自己那份关键字得靠 `@change` 另外清，否则会出现「输入框空了、候选还只剩一个」的错位 |
| 29 | 凡是把使用人当**人名**展示的候选（配对页与资产详情的选择弹窗），写 `/` 或空一律显示成灰色**「未填使用人」**，**不显示成蓝色标签里的「/」** | `/` 不是一个名字，是「没填」（见 #24）。蓝色标签的语义是"这台归这个人"，里面躺一个 `/` 会让人以为真有这么个人。判断统一走 `utils/format.ts` 的 `hasOwner()`（**空值和斜杠都算没归属**）与 `userLabel()`；`isNoUser()` 是另一回事 —— 它只判"写没写那个占位符"，对空值返回 false，配对页的过滤开关用的是它。**两个函数别混用**：做「没归属有几台」的统计时只认斜杠会少算使用人为空的那台（真实踩过：界面 11 / 断言 10，库里 `A100-01-00003` 的使用人就是空字符串）。抽成公共函数的理由是这条规则原先只写在 `PairingView` 里，而详情页的弹窗也要按同一口径显示 —— 两份必然漂 |
| 43 | 侧栏资产用 `asset_code` 当主标识，**不用 SN**；品牌型号走 `brandModel()` 去重 | 真实库里 `serial_number` **一条都没填**（v2.9.10 实测 150 台资产、0 条有值），显示「SN: —」等于没显示。而型号常把品牌名又写一遍（`brand=联想` + `model=联想LI2364A`），直接拼会显示成「联想 联想LI2364A」—— 统一走 `utils/workstationMap.ts` 的 `brandModel()` |
| 50 | 「使用人 / 点位使用人」这套**自由文本下拉**抽成 `composables/useFreeTextOptions.ts`，资产表单与地图侧栏**共用一份** | 它是 #28 那条规则（拼音筛选 + 新建项垫底）的唯一实现。原先只写在 `AssetFormDialog` 里，地图侧栏那份**只搬了一半** —— 拼音筛搬运过来了、新建项没搬 —— 于是 `filterable` 让框里能打字、**库里没有的名字却存不进去**（没有候选能对上，回车什么都不发生、`change` 不触发）。而这恰恰是这条路径最需要它的场景：**这个位置有人在用，但他用的是自己的笔记本**，台账里没有他名下那台资产，人名的候选（`meta/filters.users` 来自 assets+workstations 的 user_name 去重）里自然也没有他。抽成一份的理由：这个坑（`allow-create` 把创建项钉在最前面 + `default-first-option` → 回车存字面量）**已经因为复制粘贴踩过一次**，两份就还会有第三次 |
| 51 | 组合式函数返回 ref 时，**消费方必须解构**（`const { options: userOptions } = useFreeTextOptions(...)`），不能在模板里写 `picker.options` | Vue **不会**自动拆开"普通对象里的 ref"——它只拆顶层绑定和 `reactive` 对象。模板里写 `picker.options` 拿到的是**那个 ComputedRef 本身**，`v-for` 会把它当对象迭代，下拉里直接渲染出 `['', ()=>g.value.filter(...), 一整个候选数组, true, 132, …]` 这种东西（**实测踩到过**，所以本项目的 DOM 探针是必跑步骤，不是可选步骤）。风格与 VueUse 一致：返回 ref 组成的普通对象、调用方解构，**不要**改成返回 `reactive({...})`——那样解构的人会拿到一次性快照、静默失去响应式 |
| 52 | 台账页顶部统计卡里混着的**两种筛选轴**（`status` / `workstation`）由 `statCards[].dim` 区分；点一张卡**把另一轴清掉**；「全部设备」的高亮条件是**两个轴都没筛** | `status` 与 `workstation` 在后端是**正交**的（一台设备可以既「在用」又「没点位」——人换位置了忘了改），但**卡片这个控件是单选语义**（原来那排状态卡就是"点一下就切状态"）。不清另一轴的话会出现"点了无点位、列表却还按上一次的在用筛着"这种界面与结果对不上的状态。真想做交集，用筛选栏里那两个下拉 —— 那儿本来就是组合语义。⚠️ 「全部设备」只判 `filters.status === undefined` 是不够的：筛了「无点位」时 `status` 本来就是空的，那张卡会跟着一起亮，用户看着像"什么都没筛"，必须 `&& filters.workstation === undefined` |
| 53 | 新增一条筛选条件，**必须同时改到 6 处**，少一处就是"点了卡片列表不动"的隐性 bug | 点位轴这次就漏改了 4 处（后端 + 类型早就写好了，前端只埋了 `filters.workstation` 字段）。清单：① 后端 `services/filters.py::build_conditions` 加条件（列表 / 导出 / 盘点范围 / 聚合四个接口**共用这一个函数**，所以只要它改了、且各接口把参数透传下去就够了）；② 各接口路由的 `Query(...)` 声明；③ `schemas.py` 里需要有对应的统计字段（如 `no_workstation_count`）；④ 前端 `types.ts` 的 `AssetQuery` / `FilterOptions`；⑤ `AssetListView.vue` 里**四处**：`filters` 响应式字段、`readStateFromQuery`（URL 回灌）、`currentQuery()`（界面 → 接口/导出）、`resetFilters()`，外加触发重查的那个 `watch` 的 getter 和 `hasFilter`；⑥ `currentUrlQuery()` 会自动带上（它遍历 `currentQuery()`）。**验收要盯"点了之后列表真的重查了"，不能只盯控件高亮。** |

| # | 决策（短标题） | 理由 / 代价 |
| --- | --- | --- |
| 87 | **「持有位置」的接口必须同时给出「是什么」；主行永远是内容，宿主降为副行**（v2.9.2） | 用户把一块 M.2 装到 `A100-03-00038` 之后，**点位侧栏和资产详情页都只显示 `A100-03-00038 ×1`** —— 看不出装的是什么东西，得点开「登记配件变动」翻品类下拉才知道。**根因不在渲染层而在接口**：`HoldingOut` 继承 `HolderOut`（只回答"东西在哪"），只带 `category_id`。**判据：凡是"按宿主浏览"的上下文（点位侧栏、资产详情），品类都是未知的 —— 调用方拿不到的东西，界面永远显示不出来，所以这是接口的责任，不是调用方自己 join**。`HoldingOut` 补齐 `category_name` / `brand` / `spec` / `unit` + 单行版 `category_label`（唯一拼装实现 `light_serialize.category_label()`，口径同 `light.asset_label`）。⚠️ **反例要认清**：台账页 / 流水页那些 `display` **不动** —— 那是"按品类"的上下文，品类从标题就已知，**宿主才是那里的信息**。同一条记录在两个上下文里该显示什么，取决于**什么还不知道** |
| 89 | **默认值不替用户做决定；"这条其实有几件"要自己说出来**（v2.9.3） | 从某条持有记录点「收回库存」，数量原来**跟着那一行走**（3 套的卡 → 默认 3 套）。动机是对的（别让人以为收干净了、实际只收回一件），但**矫枉过正的代价更大**：绝大多数登记就是一件一件地走，默认 N 逼着只想收回一件的人**手动改小** —— 改错的方向正好相反。现在数量**恒为 1**，同时把信息补上：`来源共 3 套，默认只登记 1 套；整条处理请改成 3。` **通则：信息给到、决定权留给人** —— 默认值是一种"代替用户下判断"，它只在**绝大多数情况下都对**时才配存在。⚠️ 这条断言**只有在来源数量 > 1 时才有红的机会**（qty=1 的行上新旧实现都得 1，那是假绿），验收脚本因此开头就检查数据前提、不成立直接 `exit 2` |
| 97 | **聚合会把"身份"丢掉；凡是聚合后无法回答"是哪一条"的东西，就不配做成地图上的一个数字**（v2.9.6） | 地图角标「轻×3」能说的只有件数，说不出"3 套键鼠还是 1 SSD + 2 键鼠"，而轻资产恰恰是**混合池**（同一品类可分布在主机 / 人手上 / 库存）。所以 v2.9.1 的角标连同驱动它的图层开关一起删掉，位置改由搜索（可解释的命中）与点位侧栏（四组明细）承担。**判据：一个派生数字如果回答不了"点进去能看到同一件事吗"，它就是噪音。** ⚠️ 顺手把 `WorkstationOut.light_direct` / `light_via_assets` 也删了 —— 没有消费方的派生态只会变成下一次"两处数字对不上"的种子，单测里有反向断言钉住"不许加回来" |
| 98 | **"人 → 工位"只能作为**推断**给出候选，绝不能当成位置关系；有 N 个点位就把 N 个都标出来**（v2.9.6） | 人手上本来没有位置（东西可能被带回家）。但"完全不说"会让搜「键鼠」0 命中，用户只能得出"系统里没有"。折中：按"该使用人名下的点位"给**候选** —— 1 个就点亮它，N 个就 N 处全亮，每处写「按使用人的 N 个点位推断（W52、W63）」；只靠推断亮起的点位画**虚线**（确定命中仍是实线），侧栏标题写「确定 1 件 · 另有 N 件可能在」。⚠️ **不许折进任何总量**（`STATION_LIGHT_CERTAIN_GROUPS` 是这条的代码形态）：同一件东西在 N 个候选点位都会出现，相加等于把 N 个候选当成 N 份实物。⚠️ 占位符 `/` 走 `has_owner()` 排掉，否则会推断给一个叫斜杠的人 |
| 99 | **位置有歧义就显示歧义，不要为了"定下来"新增一个字段**（v2.9.6） | 用户提过"不唯一就弹窗让我选点位"。没做 —— 那个交互的实质是**写库**：加 `preferred_station_id` 等于造出第五种持有位置（`stock` / `user` / `asset` / `workstation` 之外），而"张三调去别的工位，这条配件跟不跟着走"会立刻变成无法回答的问题，重建与守恒式断言也会跟着脏。现在的做法：歧义在侧栏/搜索里明说 + 问题中心报一条 `light_user_station_ambiguous`（INFO，兜底，不是主入口），要确定位置就走真实流转（人 → 放到点位 / 装到主机），产生流水、留痕、可冲正 |
| 100 | **"库存写明点位"要算位置**（v2.9.6 推翻 v2.9.1 的 D3） | 旧口径认为 `stock_location` 只是人写的备注、不算位置关系。现场是"搜 SSD 点亮 W52、点进去说这里没有轻资产"—— 比"多算一处"糟得多。现在 `stock_location` 恰好等于某个**活着的**点位编码 → 东西就在那儿（`stock` 组），但**仍是库存、不算已分配**（`stock_quantity` 不受影响）。换算统一走 `station_ids_by_codes()`（顺带 strip 空格）；匹配不上就不算，绝不按"看起来像"硬塞 |

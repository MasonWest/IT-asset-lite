| # | 决策（短标题） | 理由 / 代价 |
| --- | --- | --- |
| 54 | 顶栏「宽屏全展开 / 手机收进「更多」」用**同一份 DOM + CSS 分叉**（`.tb-extra { display: contents }` / `.tb-more { display: none }`），**不用 `v-if` 按屏宽切两套 DOM** | `display: contents` 让那层包装**不生成盒子**，里面的按钮直接当 `.btn-group` 的 flex 子项 —— 宽屏下与"没有这层包装"逐像素一致（同 `.sheet-host` 的手法）。用 `v-if` 按屏宽切 DOM 的代价：① 断点得在 JS 里再抄一遍，和 CSS 的 `@media` 随时会漂移；② 两套按钮要维护两份 `:disabled` / `:class` 绑定，漏一处就是"桌面能点、手机点不动"；③ SSR / 首帧拿不到屏宽会闪一下。**「更多」下拉里的每一个 item 直接调宽屏按钮调的同一个函数**（`onTopbarCommand`），不写第二套实现 |
| 55 | 手机上要缩短的长文案，用 `.wide-only` / `.compact-only` **一对壳由 CSS 决定显示哪个**，**不在 JS 里按屏宽算文案** | 「已盘 12/45 **台资产**（27%）」「**不在本次范围**」这类全称在 390px 上会把一行撑爆，只能折行或被裁。但如果按屏宽在 JS 里算出不同字符串，**同一句话就维护了两份**，以后改口径（比如异常要不要进分母）必然漏一处。两个 span 都渲染、CSS 切显示，模板里读到的**永远是同一份口径**。⚠️ 代价要知道：DOM 里两个都存在，e2e 读 `textContent` 会看到拼接（本次验收输出里的 `不在本次范围范围外 (46)` 就是这个）。`display: none` 那个不进无障碍树，实际不读出来 |
| 56 | 手机端**进盘点模式就把顶部那三个全局统计隐藏掉**（`.map-page.audit-on .stats { display: none }`） | 盘点时用户要看的是"盘到哪了"（盘点条已经写得清清楚楚），不是"总点位 / 已分配 / 空闲"。而小屏上那三个数一占就是整整一行 —— 实测这一刀把工具条从 2 行收到 **1 行 53px**，直接决定画布能有多大（画布 486 → 674px）。**退出盘点自动回来**，不是永久设置。桌面端一律不隐藏（宽屏那行本来就不缺位置） |
| 57 | 手势统一走**一张指针表**（`pointers: Map<pointerId, {x,y,pan}>`）+ 显式的"手势"概念：**1 指平移 / 2 指捏合 / ≥3 指重取基准**；两指时以**两指中点为锚点**缩放 | 第一版把每个 `pointerdown` 都当同一根手指处理（第二根指头落下只是覆盖平移起点），结果就是"只能一根手指拖、捏不动" —— 想放大只能点工具条的 ±，一次 15%，还得连点七八下。三处细节：① **锚点必须换算成画布坐标**（`ax = (mx - rect.left - tx) / scale`）而不是屏幕坐标，否则捏合会变成"以画布原点缩放"、手指下的东西跑掉；② 两指**同向滑**时间距不变 → `scale` 不变、但中点变了 → 地图跟手平移，这是白送的自然行为，别去禁；③ 抬起一根手指时 `pinch.active` 要清掉并**用剩下那根手指重新做平移基准**，否则视图会按旧基准瞬移一下。缩放上下限收成 `MIN_SCALE`/`MAX_SCALE` 两个常量 —— 之前 0.2/3 散在 `fit`/`zoomBy`/`onWheel` 三处，加双指时差点只改其中一处 |
| 58 | 捏合过的这一轮手势里，**剩下的那根手指一律能平移**（`onPanEnd` 里 `rest.pan \|\| gesturePinched`）—— 比单指起手的准入规则更宽 | 单指规则是"落在点位上不给平移"（那条规则要留给"拖点位"，见决策 32）。但**点位几乎铺满画布**，捏合放大之后随手松一根手指想接着拖是很自然的动作，按单指那套执行就会得到一只死手 —— 实测第一版 26 个受控用例里**唯独这条 FAIL**，而且失败原因看上去像"手势坏了"。放宽是安全的：搬点位走的是 `mousedown`，而触摸在**发生过移动**的情况下浏览器根本不会补发 mousedown。同一个 `gesturePinched` 标记还用来挡掉抬手时补发的 `click`（否则「新增」模式下捏一下就会凭空多一个点位） |
| 59 | ⛔ **绝对不给 `.viewport` 加 `user-select: none`**（看起来无害的"防选中文本"，实测会把触摸合成的 `click` 一起吞掉） | 加这条本来只是想在拖动/捏合时别把点位上的名字、编号选成文本。**结果手机端"点点位看详情"直接失效** —— 触摸手势结束后浏览器不再补发 `click`，`.ws` 上的 `@click.stop="select(station)"` 永远不触发，表现是"点哪儿都没反应"。同一次构建里只有这一行 CSS 变了，去掉即恢复（26/26 → 25/26 → 26/26，因果确认过）。**替代方案**：真要防选中，只能让桌面端的 `pointerdown` 去 `preventDefault`，而那条又会影响 `@mousedown` 拖点位 —— 所以结论是不做，文本偶尔被选中远好过点不中点位 |
| 88 | **图标 + 文字的按钮必须 `inline-flex`，`white-space: nowrap` 救不了**（v2.9.2） | `AppIcon` 渲出的是 `<svg style="display:block">`（见 v2.9.2 修的「登记配件变动」被挤成两行）。放在普通 `<button>` 里，块级 svg **独占一行**、文字被顶到第二行 —— 这是**结构性堆叠**，而 `white-space: nowrap` 管的是文字内部折行，两件事。判据：按钮 `.lk` 改 `display:inline-flex; align-items:center`，高度 37px → 24px。**验收别拿"高度 / 行高"猜行数**（`line-height: normal` 时 `parseFloat` 得 `NaN`），也别数"内容各段的 top 是否唯一"（同一行里图标 13px / 文字行盒 16px 居中对齐，top 天然差 1~2px）—— 量**内容垂直跨度**：单行 ≈ 16px，折行 ≈ 29px，取 20px 判定 |
| 90 | **同一份数据的两种排法，必须是同一套视觉语言；`border` + `stripe` 是本项目里唯一不能用的表格形态**（v2.9.3） | 轻资产「列表」视图原来是全站唯一的 `el-table border stripe`（满屏网格线 + 斑马纹），和上面的卡片视图切来切去**像两个系统**。判据对齐「正式资产台账」的表格视图：**无外框、无竖线、无斑马纹**，只留横向细线 + 外面包一层 `.panel` 白面板；品类列 = 图标 + 名称 + 状态胶囊 + 规格副行；数字列 `tabular-nums` 右对齐；**两个视图共用同一批 chip**（同一份数据换排法，不该让人重新认一遍）；行可点进详情；操作列 `fixed="right"`。**"未登记"是状态不是数字 0**，用琥珀胶囊和真实的 0 分开。⚠️ **顺手别加列排序**：一页 20 条的前端 `sortable` 只排当前页，排出来的顺序是假的 —— 宁可没有，也不给会骗人的开关。凡"按宿主/按品类"这类**同数据多视图**，第一件事是列出两边共用的元素（chip / 图标 / 状态标），再写各自的排布 |
| 91 | **候选下拉的默认条数不许"取前 N" —— 它让人以为"库里就这么点"**（v2.9.4） | 「装到机器 / 放到点位」的候选原来 `limit=20`（后端硬上限还只有 50），而真库有 **69 个点位 / 150 台资产** —— 大半候选根本不出现在下拉里，用户以为"没得选"。现在默认 **`0` = 不限制**。⚠️ **这类 bug 的验收有个陷阱**："返回全部"与"返回前 20"在**库小的时候结果一样**（都是全部），所以只断言"候选数 == 接口返回值"是**假绿**（接口被同一个 limit 卡着，两边一起错）。必须有"候选数 > 20"这条独立断言，且脚本开头先验"库确实 > 20"、不成立 `exit 2`。取舍口径：几十 ~ 一百多条时"一次拉完"永远优于"让人反复打关键词去猜"；到几千条才该上分页 / 虚拟滚动 |
| 92 | **两种不同实体共用一个 id 字段时，切换实体类型必须把已选值清空**（v2.9.4） | 去向下拉在 `asset` 与 `workstation` 之间切换，但 `to_ref.ref_id` 是**两边共用**的一个 id 空间。选好 `asset#12` 再切「放到某个点位」，`toRefId` 还留着 `12`、候选却已整批换成点位 —— `el-select` 找不到对应 option 就把 id 原样显示成 `12`，而**点「登记」会真的照着 12 号点位提交**：不报错、但对象是错的（**静默的错比报错危险**）。判据：切换那一下清空（`switchTargetStation()`）。⚠️ **清空只能放在"用户手动切换"的 handler 里，不能塞进 `applyAction()`** —— 那条路径同时也被"从资产详情页带着对象进来"的预置流程（`applyPresetTarget()`）走，在那里清会把预置的去向一起抹掉 |
| 93 | **删掉一个维度要连"喂它的入口"一起删，否则留下的是"能填、但永远搜不到"**（v2.9.5） | 系统口径里只有点位 / 资产 / 人员，没有"房间"，而 `workstations.room` 只有 2/69 条有值。只删搜索里的 `byRoom`，用户还能在「点位详情」「批量生成」里填房间 → 填了却查不到，等于界面在承诺一件做不到的事。所以一次收口 5 处：地图搜索 / `MapStationPanel` 编辑+展示 / 批量生成输入 / `RelocationDialog` 标签 / `_station_label` 与 `light.py` 选点位搜索。**DB 列保留不迁移**（存量 2 条留着、回滚更容易），只是界面不再产生新值。⚠️ **底图里 `kind:'room'` 的矩形不在其中** —— 那是视觉分区（会议室/机房），不是点位属性，别一起删 |
| 94 | **搜索不绑图层开关；命中必须能解释，且要把"不在图上"的那部分列出来**（v2.9.5） | 用户提的方案是"点开轻资产层 → 搜索框切到轻资产"。不做，因为它把**视觉开关**变成**查询语义**：开着轻资产层搜人名会 0 命中（W52 上坐的就是员工A），关掉图层结果又消失；而且窄屏这个开关藏在「更多」下拉里，等于要三步且没有任何提示。改为：一个框全域搜，结果浮层按维度打标记（点位 / 人员 / 资产 / 轻资产），**搜索与图层开关完全无关**。更关键的是第二半：11 条轻资产里 3 条是"人持有"（不落点位）、24 台资产没挂点位 —— 只点亮地图的话，搜「键鼠」是 0 命中，用户只能得出"系统里没有键鼠"。所以浮层必须单列「不在图上」并给出口（资产 → 台账 `/?keyword=编号`；轻资产 → `/light/:id`）。**搜索宁可多说一句，也不能少说一条** |
| 95 | **索引有上限就必须把"只搜了一部分"说出来**（v2.9.5） | 资产 `page_size` 上限 1000、holdings 200。现在的库是 150 / 11，远未触顶；但资产涨到一千多台时，搜索会**静默漏结果**，界面一切正常 —— 这是最难被发现的一类假绿。判据：`total > items.length` 时浮层底部显式写「资产共 N 台，仅搜了前 M 台」。验收里用路由拦截把 `total` 伪造大 500 来走这条代码路径（否则它永远跑不到） |
| 96 | **窄屏搜索框聚焦时不许变宽**（v2.9.5） | 原来 `.search-box:focus-within { flex-basis: 150px }`，390×844 上聚焦一次就把工具条从 **87px 顶到 131px（3 行）**、C1 失守。而多出来的 42px 一个字符都多显示不了几个 —— 结果本来就在下方浮层里。改成聚焦不变宽，输入框内文本横向滚动 |
| 101 | **图标 + 文字同排的容器必须显式 flex；验收要问"有没有错位"，不能只数"画出多少个 svg"**（v2.9.7） | `AppIcon` 渲染的是 `display:block` 的 svg：容器（普通 span / button / chip）不给 flex，它就独占一行、文字掉到第二行；固定高度（28 / 36px）的按钮里文字直接溢出到按钮外，`display:block` 的 `span` 还会被撑高。**这不是样式口味问题，是渲染契约问题** —— 所以凡是"图标 + 文字"，容器一律 `display:flex/inline-flex` + `align-items:center` + `gap`，间距只由 gap 给（模板里别再写 `style="margin-right:3px"`，否则两套间距叠加）。⚠️ 验收方式：数"页面共画出多少个 svg、有没有空 path"永远是绿的（图标确实画出来了，只是位置错），**反向判据是几何** —— 取父容器文字行的垂直区间与 svg 求交，交叠不足一半就是错位（见 `.tmp/audit-icon-inline.js`）。 |
| 103 | **一张卡片里的内容块要自己补横向内边距 —— `.panel` 是不带 padding 的**（v2.9.8） | 全站口径：`.section-title` 自带 `16px 20px 8px`，其余内容块各自 `padding: 0 20px`（见 `AssetRelationsPanel`）。新组件只写了 `section.panel` 却忘了补，结果**内容贴着卡片边框、看起来"比上面的卡片宽"** —— 其实卡片同宽，是内容少了 20px 缩进。判据别量容器（容器 box 含 padding，贴着边框也可能是对的），**要量内容画在哪**：文字用 `Range.getClientRects()`，行/按钮用元素矩形，再和同页既有卡片逐像素比（21px = 1px 边框 + 20px） |
| 104 | **「图标 + 文字」的检查要扫两遍：静态扫模板 + 运行期量几何；而且不能靠"全局把 svg 改成 inline-block"一次性了事**（v2.9.9） | ① **运行期几何体检有覆盖盲区**：它只看得到"当前数据下真的渲染出来"的分支。资产详情头那两枚胶囊（`1 台显示器` / `挂在 …`）要资产真的挂了显示器/主机才渲染，而体检脚本只打开了一个没挂配件的资产 → 全站绿，bug 还在。补法：`/asset/{id}` 的 id **从接口挑**（一个有 `monitor_count>0`、一个有 `host_code`），不写死；同类条件分支（导入预览、盘点空态、地图批量面板）要么把状态造出来，要么在断言里明确写"这条没渲染出来就是失败"，不许静默跳过。② **静态扫模板是另一把网**（`.tmp/scan-icon-inline.py`）：按标签栈找每个 `<AppIcon>` 的父元素，若它同级还有文字、而父元素的类在 CSS 里没有 flex，就报。它能看到没渲染的分支，代价是有已知误报（flex 挂在复合选择器上，如 `.audit-title > span:first-child`、`.card h2`、`.view-toggle button`）→ "18 处待确认"里人工过一遍即可，最终判据仍是几何。③ **不要图省事把 `.app-icon` 全局改成 `inline-block`**：实测（`.tmp/exp-icon-inline.js`，13 个路由逐图标比对前后矩形）会把 120 处 `.ic` 纯图标容器整体推高 7.8px、图标右移 1.5px —— 因为 block→inline 会让父容器多出一个行盒。**图标是 block 是有意的（为了消掉基线空隙），所以 invariant 只能是"凡是图标 + 文字，容器必须 flex"，不能靠改图标自己**。 |

# 决策 · 导入导出

> 覆盖：列定义同源 / 空=不改 / 四桶 / 编码兜底 / 真实行号
> 回到 [决策索引](README.md) ｜ 原文快照：`docs/archive/CURRENT_STATE-v2.9.10.md`

| # | 决策（短标题） | 理由 / 代价 |
| --- | --- | --- |
| 4 | 导入/导出/模板**共用同一份列定义**（`ASSET_COLUMNS`），且**预览与落库跑同一段代码**（`build_plan()`） | 三处同源就绝不会出现"导出的列导不回来"；同段代码就不存在"预览说没事、确认就报错"。也因此不用"服务端暂存 + token"那套（token 过期、文件换了、两人互相覆盖） |
| 5 | 更新已有设备时，**空单元格 = 不修改**，不是清空 | 批量改数据最常见的是"拿两列的表把 30 台机器的使用人刷一遍"。若空=清空，一次就抹掉品牌型号 SN 位置日期且不可撤销。想清空写 `-` |
| 6 | 导入结果分**新增 / 更新 / 无变化 / 失败**四桶，报错给 **Excel 真实行号** | 少了「无变化」，同一文件导第二遍会谎报"更新了 10 条"，用户再也无法判断导入是否生效。行号是给用户直接定位用的，给内部索引 0 等于没说 |
| 7 | 中文编码三处兜底：CSV 走 `utf-8-sig` → `gbk` → `latin-1`；下载文件名走 **RFC 5987** `filename*=UTF-8''` | 中文版 Excel「另存为 CSV」默认是 GBK，不认这个用户存一遍再传就全乱码。HTTP 头是 latin-1，中文文件名必须先 `quote`，同时留 ASCII `filename=` 给老浏览器兜底 |
| 8 | `/api/transfer` **独立前缀** | `/api/assets/{asset_id}` 是路径参数路由，`/api/assets/export` 会被当成 `asset_id="export"` 抢先匹配。靠调整路由顺序躲坑意味着以后每加一条都要重想 |
| 12 | **字典数据 ≠ 业务数据**，在 `database.py` 里分成两个常量组 | 设备类型是系统能跑的最小前提（没类型没法录资产），启动时自动补；`reset.py` 只清 `BUSINESS_TABLES`，不碰它，清完界面还能正常用 |
| 13 | **启动时不灌演示数据**，只自动初始化字典 | 自动灌会让人分不清"这些设备是我录的还是系统塞的"；更糟的是误删 `.db` 后重启会凭空长出十台假设备，跟真实数据混一起，比空库更难收拾。演示数据改成手动 `python seed.py` |
| 19 | 多值筛选走**逗号分隔的字符串**（`1,3`），不用重复 query 参数（`?id=1&id=3`） | 列表页、「导出当前筛选结果」、盘点范围三处共用同一套 `build_conditions` 和同一个 `AssetQuery` 类型。逗号串让这三处一行都不用改；重复参数会逼着三处各自的参数拼装都改一遍，还容易只改对两处 |
| 38 | 点位**导入时显式忽略 JSON 里的 `assets` 字段**，并且**非空单元格才算改动、空值 = 不修改** | 原型导出的 JSON 几乎每条点位都带一个 `assets` 数组（ThinkPad / Dell，`id` 形如 `a1-W07`），和真实 `assets` 表**没有任何可对齐的键**（真实编号 `A100-01-00002`，且库里 `serial_number` 一条都没填）。读进来会凭空造出 94 台假设备混进台账。空值语义同资产导入（决策 5）：种子里 15~17 个空闲点位的 `user_name` 是空串，若空 = 清空，"导入以修正坐标"会顺手抹掉已分配点位的使用人且不可撤销 |

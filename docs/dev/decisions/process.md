| 70 | **「工位」在界面与文档里统一叫「点位」（正式名「资产点位」），但代码标识符 `workstation` / 表名 / 路由一律不改**（v2.1.0） | **为什么改称呼**：「工位」暗示"有人在这上班"，而系统里这个格子的真实身份是**位置**——会议室设备点、机房设备、备用桌、预留位都不是工位，却都是点位。换个更宽的名词，UI 文案才不用为这些场景硬拗。**为什么不动代码**：表名/列名/路由是骨架子（全表迁移 + e2e 全废 + 真实库动刀），而**用户看不见表名**，收益为零。术语映射是**文档层约定**，不是代码重构（详见第五节「术语表」）。**为什么历史文案不追改**：v2.0.0 及更早的 CHANGELOG 段、审计 `summary`、`asset_events.note` 里已冻结的「工位」是**当时的事实**，审计记录不是文案、是证据（真实库 89 条事件 + 9 条审计保持原样，只有 v2.1.0 后**新写入**的用「点位」）。**⚠️ 别把这理解成"没改干净"** —— 时间线上「工位/点位」混用是**有意**的。**同一批不要顺手改的还有**：本机素材文件名 `工位图.png`（改 `.gitignore` 失效）、用户原话引证（决策 67 保留"底图是底图，工位是工位"）。 |
| 75 | **文档改动按分级税计：默认什么都不用改，只有改口径才动 CS**（v2.3.1） | 起因是实测：加一个点位关系层要动 **8 个文件**，其中一半是文档（代码 + CS 决策 + CS 功能现状 + CS 验收表 + README + CHANGELOG + 两处版本号）。**一半的力气花在"把已经发生过的事再抄一遍"上** —— 而下次改动 90% 不会碰它，抄了也不看。**更具体的后果**：第十节验收表里手抄的"43 项通过"在改过脚本后变成 43（表格）vs 42（实际），"62 个点位"在库里多了一个之后变成 62（表格）vs 63（实际）—— **这类不同步会训练人忽略 CS**，而 CS 一旦不可信就真的废了。**做法**：① **验收表不再记数字**，数字由脚本自己打印，CS 只记口径；② **第八节不再记实施历史**（带日期的"当天做了什么"全部归 CHANGELOG），判据是"半年后有人接手时这条还有用吗"；③ 维护约定改成 **14.1 的分级表**，默认值是"什么都不用改"。**⚠️ 决策表本身要保持慢**（判据是"新加一条要不要改代码里的口径"，条数只是结果）：加决策的判据是"这条口径将来会被别人误读吗"，"我今天加了个按钮"不配进来。**红线 / 术语 / 数据模型仍然零妥协** —— 那三块照旧必改。 |
| 102 | **凡是要进库的时间，客户端只能发"本地 naive"；带时区的必须在后端入口换算成本地再去掉 tzinfo**（v2.9.8） | 现场：轻资产「起始于」比审计日志慢 8 小时。根因是前端把本地时间拼好后调了 `new Date(...).toISOString()` —— 那是 **UTC**（带 `Z`），SQLite 的 `DateTime` 列又会把 tzinfo 丢掉，于是 UTC 被当成墙上时钟存了下来。**这不是某处的疏忽，而是一条必须钉死的链路契约**：① 前端用 `localDateString()` / 手工拼 `YYYY-MM-DDTHH:mm:ss`，永不对 API 时间字段调 `toISOString()`（它也用来拼"今天"，东八区晚 8 点后会跳日）；② 后端请求里的时间字段一律 `LocalNaiveDatetime`（`app/local_time.py`，`astimezone()` 后去 tzinfo；naive 原样通过，**别好心再转一次**）；③ 例外只有文件级元信息（如地图导出 JSON 的 `exported_at`），那不是库里的数据。⚠️ 历史数据的校正判据要认**写入路径**（分钟精度 = 微秒为 0 = 浏览器写的）而不是猜数值，并且必须排除 `origin='import'`（Excel 手填的墙钟日期）|
| 105 | **许可是 Apache-2.0；`LICENSE` 只许整份下载、不许手打；`NOTICE` 只许写事实、不许写额外限制**（v2.9.10） | 公开仓库没有 LICENSE 不等于「随便用」，而是**默认保留所有权利** —— 别人连复制都不合法，README 越像产品越讽刺。选 Apache-2.0 而不是 MIT：§3 给了明确的专利授权（含报复终止）、§6 挡住 fork 冒名、§5 让 PR 默认同许可（不用 CLA），这三条正好覆盖「同事要装、客户要走法务」的场景；代价（202 行文本、再发布要带 `NOTICE` 与「已修改」标注）落在**再分发者**身上，自己部署不触发。⚠️ 三条维护纪律：① `LICENSE` 是法律文本，改一个字都可能让许可失效 —— 换版本要整份下载（apache.org），并与 SPDX 的 `Apache-2.0.txt` 做**去换行后的逐字比对**（v2.9.10 是 10221 字符全等）再提交；② `NOTICE` 按第 4(d) 条「仅供告知、不修改许可」，里面**只能写事实**（谁是原创、哪些依赖不在仓库内、哪些数据不入库），一旦写成「你不得…」就等于自己加了一条许可限制，自相矛盾；③ 将来若确认 `icons.ts` 里某几条路径沿用了第三方图标集（如 Lucide / ISC），要在 `NOTICE` 补署名 —— 现有 3 个抽查样本是自绘结构（单条 `d` 多子路径，非 `<rect>`+`<line>` 拆写），但这不构成全量证明 |

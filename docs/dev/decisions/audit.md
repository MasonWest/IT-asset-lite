# 决策 · 审计与变更历史

> 覆盖：审计两张表 / 失败也记 / IP 不可信 / 只读 / 审计页的统计卡
> 回到 [决策索引](README.md) ｜ 原文快照：`docs/archive/CURRENT_STATE-v2.9.10.md`

| # | 决策（短标题） | 理由 / 代价 |
| --- | --- | --- |
| 1 | 审计和变更历史是**两张表** | 见第五节的视角分工表，合并会让两个视角都残 |
| 2 | **失败的请求也写审计**，走独立会话 | 反复尝试删别人设备、非法状态被 409 挡下 —— 这些在业务表里毫无痕迹，恰是审计最值钱的信号。走独立会话是因为业务事务已经炸了，挂在上面写必然被回滚 |
| 3 | 审计 IP **不信任 `X-Forwarded-For`**，且用 **ContextVar** 传递 | 那个头能伪造，能自己填的 IP 让审计毫无意义（要设 `IT_ASSET_TRUST_PROXY=1` 才读）。用 ContextVar 是不想给十几个 handler 都加 `request` 参数 —— 它按异步任务隔离，不是全局变量，并发不串号 |
| 9 | 配对**解绑不删行**，改 `active=false` | 换绑轨迹才留得住 |
| 30 | 审计页顶部三张统计卡（全部记录 / 今日操作 / 失败操作）是**单选组**：任何时刻最多一张亮，判定**由当前筛选值反推**（`activeView` 计算属性），不另存一份"当前视图"状态。筛选栏的条件与日期范围被手动改过之后**三张都不亮**，那不是 bug，是"自定义视图" | 反推而不是另存，是因为存两份必然和筛选栏打架（在筛选栏选了「结果 = 成功」，卡片却还亮着「失败操作」）。原实现三处判定各写各的：`hasFilter()` **只看筛选栏、从不看时间范围**（而时间范围永远有值，默认就是近 7 天），所以点「今日操作」列表变了、蓝框却仍判定"全部记录"；「今日操作」那张卡干脆没绑条件，怎么点都不亮。**「失败操作」是开关，且只动结果维度**（不动时间范围，所以可以看"今天失败的"：先点今日再点失败）；点「今日操作」会顺手把结果条件还回去 —— 不还的话两个条件叠着，列表里还是只有失败记录，用户看到的就是"点了没反应"。卡片是单选语义，所以筛选栏的「结果」也保持单选，理由同 #16。**「重置」按钮和空状态文案都跟着这套判定走**：偏离默认（含只改了日期范围）才露「重置」；空状态文案看的是 `meta.total`（系统里到底有没有过记录），而不是"当前视图有没有结果" —— 一周前记过、这周没有时，原来会写成「还没有任何操作记录」，看着像从没记过账，其实是时间窗把它滤空了 |

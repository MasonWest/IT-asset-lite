# 决策 · 空间地图与点位

> 覆盖：点位编码 / 软删除 / 坐标画布 / 进度分母 / 搜索 / 移动端断点
> 回到 [决策索引](README.md) ｜ 原文快照：`docs/archive/CURRENT_STATE-v2.9.10.md`

| # | 决策（短标题） | 理由 / 代价 |
| --- | --- | --- |
| 31 | 点位（资产空间地图）**不建绑定表**，「资产在哪个点位」只存 `assets.workstation_id` 一处 | 关系是纯多对一，一条外键就够；流转历史由 `asset_events` 免费提供（`workstation_id` 进了 `_TRACKED_FIELDS`）。绑定表 = 同一件事存两处，必然出现"绑定表说在 A、assets 说在 B"而没人知道该信哪个 —— 与 #27 拒掉拼音列同理 |
| 32 | **点位软删除（`active=False`），编码不释放** | 物理删掉会让"这个位置曾经存在过"消失，而且 `code` 被释放后新点位可以复用同一个编码，审计里两条「W23」就再也说不清是不是同一个位置。所以软删后仍占着编码，重建同名会被 409 挡住 —— 报错要写成人话（"已删除点位的编码不会释放"），否则用户会以为系统坏了。与 `asset_relations` 解绑不删行是同一个设计 |
| 33 | 点位**删除时绝不级联删资产**：有资产先 409 + 列清单，`force=true` 也只把 `assets.workstation_id` 置空，**资产留着** | 对比：删资产会自动解绑显示器，因为配对关系是**从属于**资产的。点位方向反了 —— 资产是**借用**点位，点位只是它的位置标签，为了删标签而删掉被标记的东西因果不成立。`ondelete=RESTRICT` 是**最后一道网**（防直连 SQLite 硬删造成的孤儿引用），不是面向用户的机制；正常退役走软删除，根本不触发外键 |
| 34 | 拖动点位**攒批保存，一次提交 = 1 条审计**（`PATCH /api/workstations/layout`），而不是每松一次手发一次 | 「调整位置」是拖动 + 松手反复微调，一次排版几十次动作。逐次提交会让审计页被布局记录刷屏，真正的资产操作被淹掉 —— 与「批量导入 30 台设备 = 1 条审计」同口径。且**没有任何变化时不写**（对齐"点保存没改东西不记"）。`workstation_move` 与 `workstation_update` 也刻意分开，理由同 `ASSET_UPDATE` / `ASSET_OPERATE`：按类型筛"谁改过点位归属"时，布局微调不该混进来 |
| 35 | 地图盘点的 `empty`（空位）与 `not_in_scope`（不在本次范围）是**视图层专有的两种中性态**，不写进 `inventory_items` | 那个表的 `result` 描述的是**资产**的盘点结果，而"空点位"和"本次不盘"都不是资产结果 —— 塞进去会污染导出、筛选和统计。它们由"查不到对应行"推出来。**空位不是"盘过了"**：把什么都没盘的位置染成绿色是错误信息，与 #29 把 `/` 显示成灰色「未填使用人」同一条原则 |
| 36 | 地图盘点**必须按 task_id 显式取**（`GET /api/inventory/tasks/{id}/map-view`），不复用 `/context/{asset_id}` 的单任务假设 | `context` 取"最近一个进行中任务"，这在资产详情页合理（用户问的是"这台设备归哪个盘点"，一个答案就够）。但地图问的是「**这一片点位整体盘到哪了**」—— 聚合视图必须知道聚合的是哪一次，否则两个任务同时进行时，地图会显示一个用户没问过的任务的答案（大部分格子看似"待盘"，其实那批设备在另一个任务里早盘完了）。所以界面上有任务选择器，且**只有一个任务时也显示**（让"当前是哪一个"永远可见） |
| 37 | 地图的**进度分母用资产数**（`task.total`），不是点位数 | 盘点的对象是资产：一个点位可能挂 2 台（主机 + 显示器），也可能 0 台。拿点位数当分母，在任何点位挂 2 台时百分比都会失准。而且 `InventoryTaskOut.total` 本来就来自 `_counts()` 对 `inventory_items` 的 group by —— **直接用同一份数字，地图与原盘点页天然相等**，不用另算一套 |
| 39 | 地图顶部的进度**必须写 `已盘/应盘`，异常单独列、不计入进度**（不能写成 `(已盘+异常)/应盘`） | 一开始写的是后者，看着更"合理"（异常也算处理过了），但实测两页数字对不上：**地图 40% vs 原盘点页 20%**。原盘点页的进度来自后端 `serialize_task` 的 `checked/total`，异常只出现在「差异」里。地图要做的是一模一样的口径，而不是自己发明一个更好看的算法 —— 那正是"又做了套平行系统"。**"两页数字必须相等"是这个模块唯一的判定性验收**，任何一页的单方面优化都会破坏它 |
| 40 | 拖动点位的 `mouseup` 挂在 **document** 上，不是视口元素上 | 挂视口的话，把点位拖到视口边缘之外松手（拖到侧栏上方、或拖出窗口），拖动就永远不结束 —— `dragId` 卡在那个点位、位置变更也不进待保存集合，用户看到的是"拖了但保存按钮说没变化"。实测复现过。原型也踩过同类坑（它自己注释里写着"此前缺少 mousemove/mouseup 监听"） |
| 41 | 地图搜索用 `hasQuery` 而不是 `matchedIds.size > 0` 判断"是否在搜索" | 后者在**搜一个不存在的词**时集合为空、被判定成"没在搜索"，于是什么都不变暗也没有高亮 —— 用户以为搜索坏了。搜了但没命中的正确反馈是"全部变暗 + 图例提示没有匹配"，一眼就知道确实没这个人 |
| 42 | 地图页的搜索**也支持拼音**（复用 `utils/pinyin.ts` 的 `matchByPinyin`），与台账筛选、资产表单的使用人下拉同一个函数 | 「打首字母选人」是这个系统的既定习惯（见决策 27/28）。地图上只能打全名的话，用户会觉得这一页是外人做的。实测：`林晓薇`/`lxw` 命中，`W23` 走编码子串。**v2.9.5 起不再搜房间**（见决策 92） |
| 44 | **「所在点位」做在资产表单里**（资产台账 → 编辑），不做成"给点位挑设备" | 设备归属只存在设备自己身上（`assets.workstation_id`），所以入口自然应该跟着设备走。反过来做就得在弹窗里塞一个设备选择器，而设备有一百多台、带筛选和分页，等于把台账再写一遍。地图侧只加一个「给这个点位挂一台新设备」的快捷入口，借道 `/?new=1&workstation=23` 交给台账页处理 —— 两边各只有一条路径，不重复实现 |
| 45 | 资产表单提交时 `workstation_id` **必须显式带上**，即使是 `null` | 后端靠 `model_dump(exclude_unset=True)` 区分「没传」和「传了 null」：没传 = 不动、传 null = 从点位上摘下来。前端省掉这个键就等于**永远摘不下来**。这是"表单字段"和"后端语义"最容易错位的一处 |
| 46 | 地图侧栏「该点位暂无绑定资产」的链接指向**资产台账**，不是某台设备 | 原来写的是 `/asset/0?back=...`（用假 id 占位），点进去直接报「资产 #0 不存在」。零资产的点位根本没有目标设备可跳，只能给一个"去台账自己找"的入口。**空状态里的链接必须检查它到底指向什么** —— 占位值在开发时看着无害，用户一点就报错 |
| 47 | 点位字段的下拉标签带「已有 N 台」 | 一个人正常是主机 + 显示器共 2 台。挂到第 3 台时，标签里的"已有 3 台"能让用户立刻看出是不是挂错了点位 —— 比让他自己回想"我这人该有几台"可靠 |
| 48 | **`/map` 是唯一满铺的页面**（路由 `meta.flush` → `main.page-host.page-host--flush { max-width: none; padding: 0 }`），其余页面照旧受 1240px 阅读宽度约束。**选择器必须写两个类** | `max-width: 1240px` + `padding: 24px 20px 64px` 是为台账/列表这类"一屏文字"定的阅读宽度，套到地图上是三个错：整页被截成 1200px 居中窄块（左右各空 360px）、上下留白、总高超出视口多出一条纵向滚动条 —— 用户看到的"接进系统后地图整体缩小了"。地图要的是抬头 HUD 下面整块都是画布。**两个类不是啰嗦**：<640px 的媒体查询里还有一条 `main.page-host { padding: ... }`，它在源码里更靠后，单个 `.page-host--flush` 同特异性会被盖掉，手机上又缩回去（实测过）。**注意**：这次修的是"页框"，画布缩放比没变（修复前后都是 0.700）—— 尺寸由**高度**决定；与原型 V19 的 `0.739` 差的 5.3% 是全局 HUD 56 + 地图工具条 60 相对原型单条 64px 顶栏多出的 52px，属保留全局抬头的代价 |
| 49 | 「所在点位」下拉的编码排序**加在前端消费侧**（`utils/workstationMap.ts::compareStationCode`），**不改 `GET /api/workstations` 的顺序** | 接口给的是 `y, x, id`，那是**地图渲染**的视觉顺序（同一排的挨着给），本身没有任何问题；`SpaceMapView` 渲染用的是绝对坐标、根本不吃这个顺序。「按编码选」是**下拉这个使用场景**的诉求，不是点位数据的固有属性 —— 塞进接口等于让地图去迁就一个下拉的偏好，还会动到已有的接口断言。⚠️ **不能用 `localeCompare` 直接排**：那是字典序，`W10` 会排在 `W2` 前面，62 项里 W1x/W2x 整段插错位置，比不排还乱；必须前缀 + 数值比。自定义编码（不含「字母+数字」）统一垫在最后 |

# 前端契约与实现约定

> 图标、间距、双视图、移动端断点 —— 这四类东西的共同点是：
> **改一处看着没问题，但会在另一个页面裂开**。所以它们被集中写在这里。

### 为什么没抽手势逻辑（2026-10-08 评估结论，**别再重开这个话题**）

有人问过"把 `SpaceMapView.vue`（2740 行）里的手势逻辑抽成 composable"。**评估后决定不抽**，
理由记在这里，免得半年后又被提起来、重新论证一遍：

| 量出来的数 | |
| --- | --- |
| 文件总行数 | 2740（script 1380 / template 514 / style 843） |
| 纯手势函数 | **234 行**（12 个函数，占 script 的 17%） |
| 其中**带业务**的 | `onStageClick` 直接调 `createStation`（写库+审计+撤销栈）、`canPan` 读 `adding/editMode` |

**三条不抽的理由**：

1. **收益算不过来**：抽完 2740 → ~2600 行（**降 8.5%**），
   而要动的是 `e2e-map-pinch-0930` 那 26 项**CDP 真触摸**验收守着的地方。
2. **抽不干净**：`onStageClick` 天生带业务（创建点位 + 写审计 + 撤销栈），
   要抽出去就得传三个回调进去 —— 那是**假分离**：文件分开了，风险一分没减。
3. **它解决不了真问题**。真问题是"**改画布时怕碰坏别的东西**"，
   而抽成 composable 之后改的**照样是同一套逻辑**，只是换了个文件住 ——
   该怕的还是怕。**真正对症的是护栏**（决策 77）。

**那什么情况下该重开这个话题**：① `SpaceMapView` 超过 3500 行**且**
新增功能需要动到手势；② 要给手势写**单元测试**（当前只能靠 CDP e2e 兜）。
**届时的正确解法是拆成两个组件（地图渲染 / 侧栏与弹窗），不是抽 composable** ——
因为真正难拆的是"模板里有 10 个弹窗和侧栏"，不是那 234 行动作。


**台账页「无点位资产」统计卡（2026-09-30）**：顶掉原来的「已报废」。理由是数据：
真实库资产状态只有 `in_use` / `idle` 两种（v2.9.10 实测 124 / 26），`scrapped` 恒为 0 ——
那张卡永远显示 0、白占一格。**状态下拉里仍然保留「已报废」**，能力没丢。
点一下就是筛选（当前 53 台），走 `GET /api/assets?...&workstation=none`，进 URL、进导出。

⚠️ **这一行现在混了两种筛选轴**，`statCards` 靠 `dim` 区分（`'status'` / `'workstation'`）：
`status` 与 `workstation` 在后端是**正交**的（一台设备可以既「在用」又「没点位」——
人换位置了忘了改），但**卡片是单选语义**，点一张就把另一轴清掉。想做交集用筛选栏里那两个下拉。
连带一处容易漏的：「全部设备」卡的高亮条件是**两个轴都没筛**，
只判 `filters.status === undefined` 的话，筛了「无点位」时它也会亮，看着像"什么都没筛"。
新增筛选条件的完整清单见第七节 #53。

**列表的 SN 展示位换成「资产点位」（2026-09-30）**：卡片视图 / 表格视图 / 套装展开行三处。
真实库里 `serial_number` **一条都没填**，卡片上那行「SN 未登记」等于没信息；
`workstation_code` 只有一部分有值、且直接对应地图上的格子，扫一眼就知道这台机器在哪。
有值显示 `点位:W24`（蓝色标签 `.point-chip`），没值显示「未设点位」（灰虚线）。
**SN 没有被删掉**：详情页和编辑表单照旧显示，搜索框的 `keyword` 也仍然覆盖它
（`build_conditions` 里的 `Asset.serial_number.ilike`）—— 只是不再占据列表里那个最显眼的位置。

**「所在点位」下拉按编码顺序（2026-09-30）**：`GET /api/workstations` 的顺序是 `y, x, id`
（**地图渲染**用的视觉顺序，同一排的挨着给），照原样铺进下拉就是 `W01→W14→W27→W40…`
这种"一排跳一段"的乱序，62 项根本没法找。排序放在前端消费侧
（`utils/workstationMap.ts::compareStationCode`），**没有改接口顺序** ——
「按编码选」是下拉这个使用场景的诉求，不是点位数据的固有属性，
塞进接口等于让地图去迁就一个下拉的偏好，还会动到已有的接口断言。
⚠️ 不能用 `localeCompare` 直接排：那是字典序，`W10` 会排在 `W2` 前面，
W1x/W2x 整段插错位置，比不排还乱。必须前缀 + 数值比。

**侧栏「点位使用人」可以手打库里没有的新名字（2026-09-30）**：这个框的语义是
「**这个位置归谁**」，不是「这台设备归谁」——所以它必须接受自由文本，理由很具体：
**有人在这个位置上办公，但他用的是自己的笔记本**，台账里没有他名下任何一台资产，
人名的候选（来自 `assets.user_name` + `workstations.user_name` 去重）里自然也不会有他。
实现走 `composables/useFreeTextOptions.ts`，与资产表单的「使用人」是**同一份**
（拼音首字母筛选 + 「新建项垫底」，规则见第七节 #28）。
曾经这里**只搬了一半**：拼音筛选搬了、那个"新建"候选项没搬，结果就是
**输入框能打字、但库里没有的名字存不进去**（没有候选能对上，回车什么都不发生、
`change` 不触发）。现在两边共用一份，覆盖 22 项只读断言 + 1 项还原断言。
**注意它必须解构**（`const { options: userOptions } = ...`），理由见第七节 #51。

**资产表单的「所在点位」下拉**是另一回事：它给的是**真实点位**（`workstations` 表），
所以有 `filterable` 但没有"新建"项，也没有拼音筛选 —— 点位编码就那么几十个、
按编码顺序排（见 #49）比拼音好找。

**筛选能力（v1.0.2 起）**：四个条件参数（`device_type_id` / `status` / `user_name` / `location`）
统一支持**逗号分隔多值**，列表页与「导出当前筛选结果」、盘点范围共用同一套 `build_conditions`。
界面上：台账的类型 / 位置 / 使用人为多选（状态保持单选，见第七节 #16）；
标签打印可按类型 + 位置缩范围；配对页可按关键字搜、可只看没配显示器的主机，
给主机加显示器时默认只列未配对的。

另有两条**「要不要加这个条件」型**的参数（不是"在几个值里选一个"）：
`paired=paired|unpaired`（配没配）与 `workstation=none`（有没有落到空间点位）。
后者是 2026-09-30 加的点位轴，**与 `status` 正交** —— 详情见第八节的「无点位资产」一节
与第七节 #52/#53。

**配对页的「使用人写 `/` 的主机」默认隐藏（v1.1.1 起）**：页面顶部一个开关，默认勾上。
只作用于**主机侧**（主机列 + 待配对池的「挂到主机」下拉共用同一集合），显示器一律不筛；
开关文案直接带出台数，「只看没配显示器的」计数按过滤后重算。口径见第七节 #24、#25。

**台账筛选状态进 URL（v1.1.2 起）**：筛选条件 / 页码 / 卡片·表格视图都写在地址栏上
（`/?device_type_id=1,3&location=机房&view=table&page=2`），**刷新、收藏、发链接、前进后退都不丢**；
点进设备详情再返回，列表原样恢复。子页面的「返回」统一走 `frontend/src/composables/useBackNav.ts`：
跳转时用 `withBack()` 把当前地址塞进 `?back=`，返回时 `goBack()` 原样送回去。
注意列表更新地址用的是 `router.replace`（口径见第七节 #26）。
**代价**：地址栏会变长，列表页的 URL 不再是干净的 `/`。

**设备类型图标（v1.1.1 起）**：映射表在 `frontend/src/utils/format.ts`，
类型名精确命中优先，其次按关键字兜底（自建「显示器（曲面）」「NAS」这类名字也能命中），
都没命中才是 `📦`。**改图标前先在真实 Chromium 里渲染一遍** —— Windows 上有几个看着很合适的
码点（`U+1F5B5` SCREEN、`U+1F5B4` HARD DISK、`U+1F5C5` 空文件柜）实际是豆腐块。

**套装聚合视图（v1.1.0 起）**：台账页筛选栏右侧的「套装聚合展示」开关。开启后走
`GET /api/assets/grouped`（筛选参数与明细接口完全一致，服务端按**聚合后的行**分页），
143 行 → 96 行。卡片视图显示套装卡 + 成员 chip，表格视图带展开明细。
口径见第七节 #20~#23；实现见 `backend/app/services/bundles.py` 开头的说明。
**它是只读的展示视角**：不写数据、不产生审计、不影响导出与标签（那两者永远走设备明细）。

  （地图 40% vs 盘点页 20%）—— 而"两页一致"正是这个模块的验收标准，见决策 39。
- **地图画布比原型 V19 小 5.3%**（1920×1080 下 `0.700` vs `0.739`）。
  原因是集成后多出全局 HUD（56）+ 地图工具条（60）= 116px，而原型只有单条 64px 顶栏。
  画布尺寸由**高度**决定，所以这 52px 直接换成缩放比。**不是 bug**，见第八节。
- **`/map` 是唯一满铺的页面**（路由 `meta.flush`）。其余页面仍受 `main.page-host`
  的 1240px 阅读宽度约束 —— 改这块 CSS 时别顺手把约束整体去掉。
- **地图的移动端断点是 `900px`，而且是"三处同一个数"**。CSS 里的
  `@media (max-width: 900px)`（`SpaceMapView` 与 `MapStationPanel` 各一处）、
  `SpaceMapView` 里的 `window.matchMedia('(max-width: 900px)')`（`compact`）
  必须一致 —— 一个管画布怎么摆、一个管抽屉长什么样，对不上就会出现
  "按桌面布局算的居中 + 按手机布局画的抽屉"叠在一起。改断点要三处一起改。
- **地图手机端是"浮层抽屉"，不是"分栏"**。抽屉 `position: absolute` 盖在画布下沿
  （高度 `min(58%, 460px)`），画布**始终占满整宽**。所以：
  ① 选中点位时是 `centerOnStation()` **保缩放、只平移**，不是 `fit()` ——
     按剩余高度重算会把点位缩到十几像素、手指点不中；
  ② 抽屉挪动/开关**不会**触发 `window.resize`，靠 `watch(selectedId)` 补一次定位；
  ③ `fit()`（适应）会扣掉抽屉挡住的那截，所以**抽屉开着时按「适应」得到的是一个小图** ——
     这是"适应 = 屏幕上真能看见的都装下"的诚实结果，关掉抽屉再适应即可。
- **拖动平移在手机上依赖 `touch-action: none`**。`.viewport` 上这条 CSS 一去掉，
  触摸手势会被浏览器拿去滚页面，收不到 `pointermove`，平移直接失效。
  另外平移**只在非编辑模式**的空白处生效（编辑模式空白拖动不平移，避免和"搬点位"混淆），
  按住空格则强制平移（此时落在点位上也能拖画面）。
- **手机端手势：单指平移 + 双指捏合缩放**（`onPanStart` / `onPanMove` / `onPanEnd` 里那张指针表，见决策 57）。
  捏合**以两指中点为锚点**，所以手指底下那块地图不会跑；两指同向滑则纯平移（间距没变，缩放就不动）。
  缩放范围 `0.2 ~ 3.0`（`MIN_SCALE` / `MAX_SCALE`）。
  ⚠️ 工具条上的 `−` / `＋` / `适应` **仍然必须留在第一排**，不能收进「更多」：
  一是手势有学习成本、按钮是无成本的兜底，二是**双指手势在真机浏览器上可能被系统级手势抢走**
  （部分机型的"三指截屏 / 双指缩放页面"设置），那时按钮是唯一的退路。
- **鼠标手势不变**：空白处拖动平移、滚轮以光标为锚点缩放、右键不参与（也**不许混进那张指针表**，
  否则"左键拖 + 右键点"会被误判成双指捏合）。
- **手机端编辑类操作要多点一下**（`新增 / 删除 / 导出 JSON / 编辑点位 / 保存布局` 收在「更多」下拉里）。
  这是刻意的取舍：「盘点模式」与缩放按钮留在第一排（手机上高频），
  6 个按钮平铺会折成 2 行、把工具条顶回 178px。桌面端**完全不受影响**（全部照旧直接可见）。
- **`.wide-only` / `.compact-only` 两份文案同时存在于 DOM**，只是 CSS 藏了一份。
  所以 e2e 读 `textContent` 会拿到拼接串（如 `不在本次范围范围外 (46)`）——
  断言时**别按整串精确匹配**，用包含匹配或按数量数。见决策 55。
- **地图缩放的"地板"是 0.2、天花板 1.5**（`fit()` 里夹的），
  手动缩放 `zoomBy` 的范围是 0.2~3。手机竖屏 fit 一次大约落在 **0.365**
  （390×844 实测），此时一个点位约 29×20px —— 能点，但不算宽裕，
  所以"能平移"是这套移动端方案的必要条件，不是锦上添花。
- **「无点位资产」用的是 `workstation_id IS NULL`，不是"位置为空"**。
  两者是不同的事实：`assets.location` 是**人写的文字**（`办公室大厅-采购部` 这种），
  真实库里**几乎全部有值**；`workstation_id` 是**外键**，只有一部分落到了地图点位上（v2.9.10 实测 126 / 150）。
  所以「无点位」= 还没在地图上标过位置，不是"没有存放位置"。
- **使用人（含点位使用人）是自由文本，系统不校验、不纠错、不去重**。没有人员字典表是
  有意的（见决策 27 与红线），代价是：手打「林晓威」和已有的「林晓薇」会**并存**，
  系统不会提示"你是不是想选那个"；写 `/` 或留空表示"没归属"，靠 `utils/format.ts` 的
  `hasOwner()` 统一识别（**空值和斜杠都算没归属**，别只判斜杠）。
  好处是这份候选会**自己长**：手打一次新名字存下来之后，它下次就出现在候选里了 ——
  所以新同事的名字只需要第一次手打（决策 50）。

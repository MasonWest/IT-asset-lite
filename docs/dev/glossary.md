# 术语表

> **改用户可见文案之前必读这一篇。** 同一件事有三个称呼：
> **资产点位**（正式写法）/ **点位**（界面上的叫法）/ `workstation`（代码里的叫法）。
> 改文案只改用户可见层，不要为了"统一"去改代码标识符。

### 术语表（v2.1.0 起统一口径，改文案前必读）

同一个东西有**三个称呼**，不是三样东西。混淆它们会导致改错层：

| 层 | 名称 | 用在哪 | 能不能改 |
| --- | --- | --- | --- |
| **正式名称** | **资产点位** | 对外文档、对客户介绍、正式场合 | 定义，不改 |
| **UI 简称** | **点位** | 界面文字、按钮、提示、README、本 CS 正文、代码注释 | 就是它，别无二名 |
| **代码标识符** | `workstation` / `station` / `Workstation` | 表名 `workstations`、列 `assets.workstation_id`、路由 `/api/workstations`、变量与组件名 | ⛔ **绝不能改** |

**为什么代码标识符不改**：它是骨架子（全表迁移 + e2e 全废 + 真实库动刀），而**用户看不见表名**。
改了收益为零、风险拉满。**术语映射是文档层的约定**，不是代码重构。

> **v2.0.0 及更早的历史文档、CHANGELOG 段落、审计/时间线的历史快照里仍写「工位」** ——
> 那是**当时的事实**，不追改（审计记录不是文案，是证据）。
> 只有 **v2.1.0 之后新写入**的审计/事件文案用「点位」。

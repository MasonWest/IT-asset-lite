# 工程红线

> **这一篇的读者是"正准备违反它的人"**，所以每条都保留完整理由，不做摘要。
> 决策表里属于"约束型"的条目（不许这么改）也留在这里的完整版本，见第七节后的分册索引。

## 六、工程红线（不可违背）

**1. 「改状态」和「记历史」必须在同一个事务里。**
所有变更走 `services/events.py` 的 `record_event()`，它只 `add` 不 `commit`，由调用方连同资产改动一起提交。
审计同理：`record_audit()` 也只 `add`。这样不会出现「状态改了但历史没记」的半截数据 —— 业务回滚，审计跟着回滚。

**2. 派生状态算出来，不落库。**
「这台主机挂了几台显示器」「盘点进度百分比」都是查询时现算的，不存表。一份数据两处存，迟早对不上。

**3. 时间一律存本地时间。**
`server_default=func.now()` 在 SQLite 下编译成 `CURRENT_TIMESTAMP`，**那是 UTC** —— 东八区机器上
下午 5 点录入的设备，库里写着上午 9 点。已全部改为 `datetime.now()`，老库做了一次性平移（见决策 13）。

**4. 审计日志只读。**
`routers/audit.py` 里只有 3 个 GET 端点，**没有任何写接口**。不提供编辑，也不提供删除。

**5. 不做登录体系。**
「操作人」由用户在设置里手填（可留空），靠 IP + 手填操作人区分。**不要自作主张加登录。**

**6. 启动流程只建表 + 补字典，绝不写业务数据。**
`lifespan` 里只允许调 `ensure_schema()` 和 `ensure_dictionary()`。想加"启动时顺便灌点什么"
之前先想清楚：删掉 `.db` 重启应该得到一个空库。演示数据只能由 `python seed.py` 显式触发。

**7. 新增/删除表要同步 `database.py` 的表分类。**
`BUSINESS_TABLES`（业务数据，`reset.py` 会清）和 `DICTIONARY_TABLES`（基础数据，自动补、不被清）
是人工维护的名单，`ASSET_COLUMNS` 那条红线同理 —— 漏一个就会让 `reset.py` 留下残缺数据。

**8. 前后端的"生效方式"不是一回事：改了 `.py` 必须重启进程，改了前端 `vite build` + 刷新即可。**
前端是 `dist` 里的静态文件、每次请求现读；**后端 Python 只在进程启动那一刻加载一次**。

**9. 真实库不许跑会写数据的验收脚本，一律另起临时库。**
`.gitignore` 保得住数据文件不进仓库，**保不住脚本把数据改脏**。2026-10-02 一天内踩到**三次**：
`e2e-floor-editor.js`（含"新增图元→保存"和"批量生成→撞码"两组写操作）被打到真实库上，
一次留下 6 个测试点位 + 1 条脏审计，一次把 `r1.x` 改掉、塞进一个 `r9 新房间`、
还把 `entry` 图元弄丢（因为脚本 F 段保存的是它自己改过的 layout）；
第三次是 `e2e-bulk-move.js` —— 它的 `BASE` 曾写成 `process.env.E2E_BASE || 'http://127.0.0.1:8080'`，
**不设环境变量就默认打到用户的真实库**，一次留下 7 个点位（`W6738xx`）+ 9 条脏审计。
→ **口径**：任何带写操作的验收必须
`cp backend/data/it_assets.db .tmp/verify-x/it_assets.db` +
`IT_ASSET_DATA_DIR=<abs .tmp/verify-x> python run.py --port 8099`，跑完删目录。
纯只读脚本（`e2e-floor-legacy-parity` / `e2e-v1xx` / `e2e-map-ux` / `e2e-nopoint-mobile`
/ `e2e-map-pinch` / `e2e-station-relation`）才可以对真实库跑。
**跑之前先看脚本里有没有 `POST`/`PUT`/`PATCH`/`DELETE`。**
**写操作脚本一律不许有"默认真实库"的兜底** —— `e2e-bulk-move.js` 现已改成
**不设 `E2E_BASE` 直接 exit 2**（fail-closed），并额外拦截 8080。
**"贴心"的默认值在有写操作时是危险品。**

**10. 公开仓库前必须做隐私扫描，.gitignore 只能挡未来。**
真实姓名 / 资产编码 / 办公室平面图一旦进了 commit，就算后来删掉，**历史里还在**。
`git ls-files` 看到的才是"会被推上去的东西"，`git status` 里那些 `??` 未跟踪文件同样危险
（一次 `git add .` 就全进去了）。见决策 69。

**11. 用户报"界面像代码 bug"时，先确认"跑的是不是新代码"（前后端生效方式不同，见第 8 条）。**
看第 8 条。它和这一条最容易混为一谈，代价是真实的：2026-09-30 那轮"「无点位资产」卡显示 0 且点了不筛选"，
排查了一圈发现**代码一个字没错**，只是 8080 上那个进程比改代码早启动了 7 分钟 ——
它返回的 `meta/filters` 里没有新字段（前端拿到 `undefined` → 显示 0），
也不认 `?workstation=none`（FastAPI 对多余的 query param 直接忽略 → 点了没反应）。
→ **口径：怀疑界面出问题之前，先 `curl` 一下接口确认"跑的是不是新代码"。** 这一条能省掉一整轮白干。

# 问题中心与关联操作建议

## 问题中心怎么用

导航栏第二个入口。它回答三个问题：

1. **现在有什么值得看一眼** —— 第一行就是结论（"2 件事需要核对，32 条提示"）。
2. **为什么值得关注** —— 每类问题一句话说清来由。它**不制造焦虑**：
   待核对走琥珀、提示走灰蓝，**没有红色**。因为"点位没人 + 挂着有主的设备"这类
   是公共设备、备用机、会议室机器的正常形态 —— 把正常当异常，你会很快学会无视这一页。
3. **我能直接做什么** —— 每条问题都带一个按钮，点了**真的跳到那个地方**：
   「去地图核对」会选中那个点位、「去挂靠点位」会筛出所有没点位的设备、
   「去补使用人」直接打开那台设备。

几条你需要知道的规矩：

- **没有"已处理"按钮，这是有意的。** 问题每次打开现算：你去做完真实操作（补上使用人、
  把设备挂到点位上），它下次自己就不出现了。所以界面上不会有"点一下假装解决"这种操作。
- **状态也会被看一眼。** 一台设备状态写着「在库」，可它挂在有人使用的点位上、使用人
  还是那个人 —— 三样信息里两样说"这人正在用它"，就会被列成待核对。它在**点位侧栏的
  关系核对卡片**里同样看得到，也在那儿「确认例外」：备用机、还没验收的机器都长这样。
  系统**不会**替你改状态 —— 哪台真在用只有人知道；真要改，卡片上的按钮直接带你到
  设备详情，那里有「领用」。
- **确认过的例外仍然看得见。** 某处差异确实合理（比如那个位置就是共用的），
  在空间地图的点位侧栏把它记为「例外」并写明理由。之后它**不计入待办**，
  但在问题中心仍然列着、能看见、能撤销。
- **例外会自己失效。** 只要相关关系变了（改了使用人、换了设备），
  当初那条确认就自动作废，差异会重新冒出来提醒你再看一眼 —— 不需要你手动清理。
- **导航上的数字只在"有待核对"时出现**（琥珀色，不是红色）。

## 关联操作建议怎么用

这是"操作之前先帮你想一步"：给一个**原本没人**的点位填上使用人时，
系统会先看一眼这个点位下挂的设备，然后问你一句"要不要顺手把设备使用人也对上？"

- **没登记使用人的设备** → 默认帮你勾好，确认就一起填上新使用人。
- **已经是这个人的设备** → 不来烦你（只提示有意义的变化）。
- **设备已经登记了别人** → 列出来让你自己拍板（默认不勾）—— 系统不会替你覆盖。
- **公用 / 共享设备** → 提示"可以保留现状"，不强迫绑到某个人名下。

你可以全部同步、只勾几台、或者点「暂不处理」—— 暂不处理也没关系，
没对上的差异会留在问题中心，随时能找到。就算你在弹窗开着的时候别的页面改了设备，
系统执行前也会重新核对一遍，不会拿旧数据硬盖。

**反过来也管：清空点位使用人时**，如果这个位置上还有设备登记着那个人的名字，
系统会问你一句"一并清除，还是保留？"—— **默认一个都不勾**，
因为设备很可能属于岗位而不是个人（人走了、机器留给下一任，这种情况就该保留）。
值得提醒一句：点位清空之后残留的名字，问题中心**不会**替你盯着
（它只在"点位有人"的时候做对照），所以这一刻是挡下它的最好时机。

> 换人（换另一个人接手）、挂设备、点位迁移这三个动作**刻意不做**这种提示 ——
> 挂设备你自己心里有数（共用机很常见）、迁移有自己的预览对账、换人则
> 一次弹一堆反而容易误改。这一条是量过真库使用数据之后定的。

# 盘点

一次盘点 = 一个任务。发起时圈定范围，过程中逐台标记，最后看差异、导出。

## 发起一次盘点

导航栏「盘点」→ 发起任务：

1. **圈范围**：按类型 / 状态 / 使用人 / 位置 / 关键字。
2. **看分母**：填范围时页面会**实时预览会盘到几台** —— 这个数字就是本次的「应盘」，
   发起之后就固定下来了（快照）。
3. 确认发起。

> 分母是**资产台数**，不是点位数。因为一个点位可能挂 2 台（主机 + 显示器），
> 也可能一台都没有 —— 拿点位数当分母，任何"一格里两台"的排布都会让百分比失准。

## 标记

三条路，随你顺手，**结果完全一致**（同一份数据，三个视角）：

| 在哪标 | 怎么标 |
| --- | --- |
| **盘点页** | 列表里逐台点「已盘 / 异常」，异常要写一句说明 |
| **手机扫码** | 扫设备上的二维码 → 详情页顶部直接出现「标记已盘 / 异常」 |
| **空间地图** | 「盘点模式」→ 点点位 → 详情里逐台标，或「一键把这个点位的设备全部标为已盘」 |

盘点点「标记异常」时写的那句话，会跟着结果进导出表格的「盘点备注」列（比如「位置不对，实际在 4F」「SN 对不上」）。

⚠️ 如果提示「设备不在这轮盘点的范围里」：这轮盘点发起时圈的范围不含它（比如你只盘了「显示器」类型）。按同样范围再发起一次，或把范围放宽。

## 看结果

- **差异清单**：盘完看哪些没盘到、哪些标了异常。
- **导出**：xlsx / CSV，含盘点备注。
- **地图与盘点页数字必须一致**：都是「已盘 / 应盘」，**异常单独列出、不计入进度**。
  两页对不上就是 bug —— 这条是地图盘点的验收标准。

## 和"点位关系"的关系

盘点找的是"实物和账面不一致"。而[问题中心](insights.md) 找的是"账面内部自相矛盾"
（点位使用人和设备使用人对不上、设备没落到点位、设备没登记使用人）。
两者互补，互不替代：盘点需要人拿着手机走一圈，问题中心是打开就有的线索。

# 常见问题与已知限制

## 常见问题

**接口报错 / 页面空白？**
后端没起来。看启动窗口有没有报错，或访问 `http://127.0.0.1:8080/api/health`，正常会返回 `{"status":"ok"}`。

**提示「前端尚未构建」？**
`frontend/dist` 不存在。执行 `start.bat --rebuild`，或手动 `cd frontend && npm install && npm run build`。

**端口被占用？**
默认 8080，被占了 `start.bat` 会自动往后找并在控制台告诉你。手动指定：`set IT_ASSET_PORT=18080` 再 `start.bat`。

> 注意：**8000 端口不要用**。这台机器上装了 C-Lodop 打印服务，它长期占着 8000 和 18000。

**我删了数据库，重启后怎么又长出一堆设备？**
以前会，现在不会了。启动时只建表 + 初始化设备类型，**不写任何资产**。删掉 `backend\data\it_assets.db` 重启，得到的是空库（设备类型 6 个、设备 0 台）。要演示数据得自己跑 `python backend\seed.py`。

**启动后台账是空的，示例设备哪去了？**
同上 —— 演示数据不自动灌。`python backend\seed.py` 就有了；`--check` 可以只看各表条数、不做任何写入。

**怎么把系统清空成一张白纸？**
`python backend\reset.py`。先自动备份到 `backups\`，列出将删除的内容，然后要你亲手输入 `RESET` 才动手。设备类型和表结构都留着。想先看会删什么：加 `--check`（一个字都不写）。

**配对 / 送修点了没反应，提示要填操作人？**
系统没有账号体系，所有写操作都要记「谁做的」。点右上角 👤 按钮填一次名字，存在你这台设备的浏览器里，之后就不用再填了（留空也能用，只是只剩 IP 能区分）。

**「已报废」的设备领用不了？**
故意的。报废设备只能「恢复入库」回到在库状态，然后才能领用。非法流转后端会拦下并说明原因。

**点进设备详情，返回后台账的筛选没了？**
v1.1.2 起不会了。台账的筛选 / 页码 / 视图都写在地址栏上，详情页的「返回」会照着原样恢复。地址栏会因此变长（例如 `/?device_type_id=1,3&page=2`），这是正常的 —— 它就是当前列表的完整状态，可以直接收藏或发给同事。

**点「+ 加显示器」说没有可选的？**
配对只认「类别 = 显示类」的设备类型。如果新增了一个「一体机」类型但类别是「其他」，它不会出现在这里 —— 到「设备类型」里把类别改成显示类即可。

**配对管理里，主机怎么少了几台？**
被页面上方那个过滤开关挡住了。使用人填 `/`（或全角 `／`）是「这台不归谁」的写法 —— 公共大厅、资料室那类机器常这么写，它们多半没有显示器，却会把真正要配的机器淹掉（实测 19 台待配里占了 13 台），所以默认不显示。想看就把那个开关取消勾选。想让某台机器彻底回到列表里，到它的详情页把使用人改成真实姓名或留空即可。**显示器不受这条规则影响** —— 显示器就算写了 `/` 也照样列出来，因为它还得有人给它找主机去挂。

**盘点标记提示「设备不在这轮盘点的范围里」？**
这轮盘点发起时圈定的范围不含这台设备（比如你只盘了「显示器」类型）。按同样范围再发起一次，或发起时把范围放宽。

**导入时把某台设备的一个字段清空了怎么办？**
正常不会。更新已有设备时，**空单元格表示「保持原值不变」**，不是清空。只有你明确写了 `-`（或 `空` / `null`）才会把那格清掉。所以「拿一份只有两列的表刷使用人」是安全的，不会顺手抹掉品牌型号。

**导出再导回来，为什么显示「无变化」而不是「更新」？**
因为它真的没变。导出列和导入模板列是同一份定义，原样导回去本来就应该是零改动 —— 这恰恰是列对齐的证明。

**导入之后设备没进去 / 数量对不上？**
看导入结果页的四个数字：`新增成功 / 更新成功 / 无变化跳过 / 导入失败`。失败大于 0 时下面会逐条列出是哪一行、什么原因。**有错的行会被跳过，其余正常的行照常入库**，不会整份文件白干。

**CSV 导入进去中文变乱码？**
系统导出的 CSV 带 BOM，没问题。如果是你自己在 Excel 里「另存为 CSV」，中文版 Excel 默认存成 GBK —— 这个也认。再不行会退回 latin-1 兜底，保证不会因为编码直接崩掉。

**能像别的系统那样，用手机摄像头对着设备直接扫吗？**
不行，这是浏览器的硬限制：调摄像头必须 HTTPS 或 localhost，而本系统是局域网 `http://192.168.x.x`。所以改用系统相机 / 微信扫设备上已经贴好的二维码 —— 效果一样，而且微信里也能用。

**审计日志能删吗？**
不能，这是故意的。页面上没有编辑删除入口，后端只有 3 个 GET 接口。要长期归档就用 `backup.bat` 备份整个数据库文件。真想物理清空，跑 `python backend\reset.py`。

**备份文件越攒越多？**
`backup.bat` 默认只保留最近 30 份。想留更多：`python backend\backup_db.py --keep 365`。

## 已知限制（这些是**故意**的，不是没做完）

每条都是"看起来像 bug 的有意设计"。改代码前先看这里，否则很容易把有意的设计当 bug 改掉。

- **不能用手机摄像头实时扫码**。浏览器要求 HTTPS 或 localhost 才能调摄像头，而本系统是局域网 `http://192.168.x.x`。改用系统相机 / 微信扫已经贴好的二维码 —— 效果一样。
- **没有登录和权限**。这是有意的（见红线 5），「操作人」靠手填 + IP 区分，不能作为强身份证明。
- **没有附件**（发票、保修卡照片），没有保修到期提醒。
- **审计日志不能删**。数据量大时只能靠筛选和分页，没有归档/清理功能。
- **导入是同步的**。超大文件（上万行）会让请求变慢，目前没有后台任务队列。
- **`frontend/dist` 需要 Node 才能构建**。把 dist 一起拷过去，目标机器不装 Node 也能跑。

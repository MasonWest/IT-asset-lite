# IT 资产管理系统

办公室 IT 设备的台账工具。**录入 → 扫码查详情 → 主机显示器配对 → 状态流转 → 盘点 → 批量导入导出 → 操作审计**，一条命令起服务。

- 每台设备有一个二维码，贴到机器上，手机扫一下就能看到这台机器的全部信息
- 显示器到底挂在哪台主机上，一张页面看清、一步改完
- 领用 / 归还 / 送修 / 报废都记进变更历史，每台设备一条时间线
- 盘点用手机扫码就能逐台标记，最后导出差异报表
- 一批新电脑到货？下载 Excel 模板填一遍导进去，导入前先给你看清楚要改什么
- 谁把哪台设备改成了什么，审计页一条条记着（时间 / IP / 操作人 / 对象 / 变更内容）
- 支持批量打印二维码标签（A4 纸上直接打，剪下来贴）
- 手机浏览器打开就能用，不需要装 App
- 一个 `start.bat` 双击就跑，`backup.bat` 双击就备份

## 第二阶段做了什么

解决「显示器比主机多、谁挂谁说不清」这个问题，外加把设备从入库到报废的一生记下来。

| 能力 | 说明 |
| --- | --- |
| 主机 ↔ 显示器配对 | 一台主机可挂多台显示器；一台显示器同一时刻只能挂在一台主机上 |
| 双向可见 | 主机详情页列出「配了哪些显示器」，显示器详情页显示「挂在哪台主机上」 |
| 换绑 / 解绑 | 从别的主机拿走显示器走「换绑」，一次事务里解绑 + 绑定，不留悬空关系；解绑不删记录 |
| 配对管理页 | 左边待配对池、右边主机列表，拖不清的时候一眼看出哪台显示器没主 |
| 状态流转 | 在库 / 在用 / 维修中 / 已报废 四态，操作有 领用、归还、送修、维修完成、报废、恢复入库 |
| 非法流转拦截 | 状态机在服务端，例如「已报废」的设备不能再领用，直接 409 并给出人话原因 |
| 变更历史时间线 | 录入 / 信息变更 / 状态流转 / 配对解绑 / 盘点标记 全记在 `asset_events`，每台设备一条倒序时间线 |
| 盘点任务 | 按类型 / 状态 / 使用人 / 位置 / 关键字圈定范围，发起时实时预览会盘到几台 |
| 扫码盘点 | 手机扫设备上的二维码 → 落到详情页 → 顶部直接出现「标记已盘 / 异常」按钮 |
| 盘点结果 | 已盘 / 未盘 / 异常 三态，进度环 + 差异清单 |
| 导出 | 全量或只导差异，xlsx / CSV 都行，CSV 带 BOM 不乱码，中文文件名不乱码 |

**本阶段不做**（按总约束）：采购、合同、财务、工单、审批流。

### 两个设计取舍，值得知道

**1. 盘点为什么不做摄像头扫码。**
浏览器调摄像头必须满足 secure context —— HTTPS 或 localhost。本系统是局域网 `http://192.168.x.x`，手机上 `getUserMedia` 会被浏览器直接拦掉，引任何扫码库都救不回来。

所以改成：**用手机自带相机或微信，扫设备上那张已经贴好的二维码** → 打开详情页 → 顶部自动出现盘点条。不需要摄像头权限、不需要 HTTPS，微信内置浏览器里也能用。

**2. 设备类别是单独的字段，不是按名字猜的。**
设备类型的名字用户可以随便改（把「主机」改成「工控机」），所以另存了一个 `category = host / display / other`。名字随便改，配对能力不受影响。

## 第三阶段做了什么

解决三件事：**出了事查不到人**、**一批设备只能一台台敲**、**换台电脑部署要折腾半天**。

| 能力 | 说明 |
| --- | --- |
| 操作审计 | 新增 / 编辑 / 删除 / 状态流转 / 配对 / 解绑 / 换绑 / 盘点 / 导入 / 导出，每一次写操作都留一条：时间、操作人、IP、操作类型、操作对象、变更内容 |
| 失败的尝试也记 | 反复试删别人设备、状态非法被 409 挡下来，这些在业务表里毫无痕迹，恰恰是审计最有价值的部分 |
| 审计页 | 时间线式只读列表，可按日期 / 操作类型 / 操作人 / IP / 结果 / 关键字筛选，可展开看结构化明细 |
| 审计日志只读 | 界面上没有编辑删除入口，后端也只有 3 个 GET 接口。日志只追加，不修改，不删除 |
| 审计导出 | xlsx / CSV，导出「当前筛选」或「全部」；导出动作本身也记一条审计 |
| 导入模板 | 一页 xlsx 三个工作表：资产导入（含 2 行示例）/ 填写说明 / 列说明 |
| 批量导入 | 支持 .xlsx / .csv；**先预览再落库**；可选「仅新增」或「新增或更新」 |
| 逐行校验 | 编号必填且唯一（文件内重复会指出跟第几行撞了）、类型必填、日期格式、状态取值、字段超长 |
| Excel 行号定位 | 报错直接说「第 7 行：日期格式无法识别」，你照着行号在 Excel 里就能找到那一格 |
| 设备类型自动创建 | 类型名不存在时可选「自动创建」或「逐行报错」，按名字猜类别 |
| 导入结果 | 新增 / 更新 / 无变化 / 失败四个桶如实分开计数；失败行逐条列出原因 |
| 导出资产 | 当前筛选或全部，xlsx / CSV，可附带配对的显示器信息 |
| 列完全对齐 | 导出列 = 导入模板列（同一份 `ASSET_COLUMNS` 定义），所以「导出 → 改一改 → 导回来」必然能跑通 |
| `start.bat` | 双击：查 Python → 建虚拟环境 → 装依赖 → 构建前端 → 起服务 → 自动开浏览器 |
| `stop.bat` | 双击停止服务（按端口找到 python 进程优雅结束，不误伤别的程序） |
| `backup.bat` | 双击把数据库备份成 `backups/it_assets_20260924_101100.db`，默认只留最近 30 份 |

**本阶段不做**：登录体系、权限、审批流。审计的「操作人」靠用户在右上角自己填，留空也能用（靠 IP 区分）。

### 四个设计取舍，值得知道

**1. 审计和变更历史是两张表，不是一张。**
`asset_events` 是**设备视角**（挂在设备下，给那台设备的时间线看）；`audit_logs` 是**操作者视角**（一次操作一条，带 IP 和成功标志）。批量导入改了 30 台设备 → 时间线 30 条，审计 1 条。合并成一张表，两个视角都会瘸。

**2. 导入更新时，空单元格 = 不修改，不是清空。**
现实里批量改数据最常见的是「拿一份只有两列的表，把 30 台机器的使用人刷一遍」。如果空值等于清空，这一下就把品牌、型号、SN、位置、日期全抹了，而且不可撤销。真想清空某个字段，就在那格写一个减号 `-`。

**3. 预览和落库跑的是同一段代码。**
`build_plan()` 解析 + 校验，预览拿到结果就不往下走，落库接着往下走。所以不会出现「预览说没问题、一点确认就报错」。也因此不用「服务端暂存 + token」那一套 —— 少一份状态就少一类 bug（token 过期、文件被换、两个人同时导入互相覆盖）。

**4. 失败请求走独立的审计写入路径。**
成功的业务操作和它的审计同事务提交，业务回滚审计跟着回滚（不会「记了却没改」）。失败请求的业务事务已经炸了，挂在上面写必然被回滚 —— 所以另开一个会话、自己提交、异常全吞，而且审计失败绝不会把 500 变成更糟的东西。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Python 3.10+ / FastAPI / SQLAlchemy 2.x |
| 数据库 | SQLite（文件在 `backend/data/it_assets.db`，自动创建） |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus |
| 二维码 | 后端用 `qrcode` 生成 PNG |
| 表格 | 后端用 `openpyxl` 读写 xlsx（模板 / 导入解析 / 导出） |
| 部署 | 单体应用：前端构建产物由后端一起托管，只跑一个进程、一个端口 |

不依赖 Docker，不需要 Nginx，不需要微服务。

## 快速开始

### 方式一：双击 `start.bat`（推荐）

脚本会依次做：检查是否已在运行 → 挑一个可用端口 → 找可用的 Python → 检查依赖 → 构建前端页面（首次）→ 启动服务 → 5 秒后自动打开浏览器。

**它用的是你电脑上已经装好的 Python，不会创建虚拟环境，也不会自动往你的 Python 里装东西。**

依赖只需要手动装一次：

```bat
python -m pip install -r backend\requirements.txt
```

装完以后，每次双击 `start.bat` 就只是「找 Python → 起服务」，几秒钟的事。如果提示缺依赖，脚本会告诉你缺哪几个包，并打印一行可以直接复制粘贴的命令，照做一次就行。

看到下面这些就说明起来了：

```
  电脑访问   http://127.0.0.1:8080
  手机扫码   见下面控制台里「手机扫码」那一行
```

浏览器会在 5 秒后自动打开。想停止服务，**在这个窗口按 `Ctrl+C`**，或者**另外双击一次 `stop.bat`**。

#### 三个脚本的分工

| 脚本 | 干什么 | 什么时候用 |
| --- | --- | --- |
| `start.bat` | 检查环境 → 装依赖 → 构建前端 → 起服务 → 开浏览器 | 日常启动 |
| `stop.bat` | 按端口找到正在监听的 `python.exe` 并结束它 | 忘了服务在哪个窗口 / 窗口关了但进程还在 |
| `backup.bat` | 把数据库备份成 `backups/it_assets_年月日_时分秒.db` | 定期备份，或动数据之前先存一份 |

`stop.bat` 只结束 `python.exe`。如果那个端口被别的程序占着，它会告诉你「不是本系统，跳过」，不会误伤。

`backup.bat` 走的是 SQLite 的**在线备份接口**，服务正在运行、有人正在录入也能拿到完整一致的数据（直接 copy 文件在写入时有概率拿到写了一半的页面）。备份完会做一次完整性校验，校验不过会删掉那个文件并报错 —— 不会给你留个 0 字节的「成功备份」。默认只保留最近 30 份，更早的自动清理。

#### 启动脚本的几个细节

- **端口是自动挑的。** 从 8080 开始，被占用了就往后找 8081、8082…，并在控制台告诉你实际用的是哪个。不想让它自动挑：`set IT_ASSET_PORT=18080` 再运行。实际使用的端口会写进 `.tmp/last-port.txt`，`stop.bat` 靠它定位。
- **重复双击 `start.bat` 不会起两个服务。** 它会先探一下上次用的端口，发现接口还在响应就直接帮你打开浏览器，然后退出。
- **脚本怎么找 Python：** 按 `py -3` → `python` → `python3` 的顺序逐个**实测** —— 先试着用它跑一次依赖自检，能起来且依赖齐全才采用。不是简单地取 PATH 里第一个，因为电脑上可能装了好几个 Python，PATH 排第一的未必是装了依赖的那个。`py -3` 优先是因为它是 Windows 官方的启动器，指向系统里正式安装的 Python，不受 PATH 顺序影响。
- **想知道当前用的是哪个 Python、缺什么依赖：** 执行 `python backend\check_env.py`。它会打印解释器完整路径、每个依赖的版本、缺了哪几个、以及可直接复制的安装命令。
- **`start.bat` / `stop.bat` / `backup.bat` / `dev.bat` 都是 GBK 编码的。** 这样中文提示在 Windows 控制台（代码页 936）里才正常。改了这几个文件的话，**记得存成 ANSI/GBK 编码**，存成 UTF-8 中文会变乱码。
- **想重新构建前端：** `start.bat --rebuild`。

### 方式二：手动启动

**后端**

```bash
pip install -r backend\requirements.txt    # 只需装一次
cd backend
python run.py                              # 默认 8080 端口
```

`run.py` 可以从任意目录执行。换端口：`python run.py --port 18080`，或者设环境变量 `IT_ASSET_PORT=18080`。

> 想用虚拟环境做隔离当然也可以，自己建就行（`python -m venv .venv`）。只是脚本不会替你建 —— 现在默认直接用系统里装好的 Python，少一层出错的可能。

**前端（只用开发模式时才需要）**

```bash
cd frontend
npm install
npm run build                     # 构建产物交给后端托管
```

开发时用 `npm run dev`，Vite 会把 `/api` 代理到 `http://127.0.0.1:8080`。

### 数据库怎么备份

双击 `backup.bat` 就行。它会打印出数据库文件和备份目录的完整路径，一眼能看清东西在哪：

```
数据库文件：E:\IT_snipe\backend\data\it_assets.db
备份目录  ：E:\IT_snipe\backups

[完成] 已生成备份：it_assets_20260924_101100.db
       大小 192.0 KB，包含 10 台设备
```

命令行等价写法（想改保留份数时用这个）：

```bash
python backend\backup_db.py --keep 100
python backend\backup_db.py --list      # 只看不建
python backend\backup_db.py --out D:\bak # 换目录
```

**恢复**：停掉服务，把 `backups\it_assets_xxxx.db` 复制成 `backend\data\it_assets.db`（覆盖），再启动。恢复前建议先把当前那份改个名留一手。

## 局域网内其他设备怎么访问

服务默认监听 `0.0.0.0`，也就是说**同一局域网里的任何设备都能访问**，不需要额外配置。手机不用装 App，别的电脑也不用装。

**第一步，拿到电脑的局域网地址。** 启动服务时控制台会打印一行：

```
手机扫码 : http://192.168.1.23:8080
```

那个 `http://192.168.1.23:8080` 就是让别的设备访问的地址。

**第二步，在别的设备上打开它。**

- **手机**：连上同一个 Wi-Fi，浏览器地址栏输入这个地址。或者更省事 —— 打开某台设备的详情页，用手机相机 / 微信扫页面上的二维码，直接跳到那台设备的详情页。
- **另一台电脑**：浏览器输入同样的地址即可。

**第三步（只在打不开时才需要），放行防火墙。** Windows 默认会拦掉外部访问 8080 端口。用**管理员身份**打开 PowerShell 或 CMD，执行一次：

```bat
netsh advfirewall firewall add rule name="IT资产管理8080" dir=in action=allow protocol=TCP localport=8080
```

（端口如果被自动顺延到了 8081，把上面命令里的 8080 换成实际端口。）

### 扫不出来 / 打不开怎么办

**先查防火墙。** 见上面第三步。

**再查 IP 对不对。** 电脑上有 VPN、虚拟机（VMware/VirtualBox）、WSL 的时候，程序自动探测到的网卡地址可能是用不了的那个。在 CMD 里执行 `ipconfig`，找到你正在用的那个网卡的 IPv4 地址（一般是 `192.168.x.x` 或 `10.x.x.x`）。

然后点右上角 **⚙ 设置**，把「自定义扫码地址」填成：

```
http://192.168.x.x:8080
```

保存。二维码会立刻按新地址重新生成。

**想改端口？** 三个办法，任选一个：

```bat
set IT_ASSET_PORT=18080
start.bat                    :: 当前窗口临时生效
```

```bat
setx IT_ASSET_PORT 18080
:: 永久写进用户环境变量，之后新开的窗口都生效
```

或者直接 `python run.py --port 18080`。改了端口之后，二维码地址会自动跟着变，不用手动改设置。

其他可能：

- 公司 Wi-Fi 开了「AP 隔离 / 客户端隔离」，同一 Wi-Fi 下设备也互相访问不了。这种情况要么关掉隔离，要么用手机热点让电脑连上，再按热点网段填地址。
- 地址里的端口和服务实际用的端口不一致。看启动窗口打印的那个端口，以它为准。

### 第三阶段

先做一件事：**在右上角把「操作人」填上**。审计要记「谁干的」，没填的话记录里的操作人是空的（能记 IP，但看不出是谁）。

#### 1. 改一台设备状态，审计页能看到「时间 + IP + 操作 + 对象 + 变更内容」

1. 进 `IT-2026-0001` 详情页 → 右上角 **状态操作 ▾** → **🔧 送修** → **确认送修**
2. 顶部导航点 **审计日志**（记录为 0 的话说明服务刚重启过，正常）
3. 第一条就是刚才那次操作，一行里能看到全部五样东西：
   - **操作类型**：状态流转
   - **操作对象**：`IT-2026-0001 · 联想 ThinkCentre M720t`
   - **变更内容**：`送修：状态 在用 → 维修中`
   - **时间 / IP / 操作人**：下面一排小标签（`👤 你的名字`、`🌐 192.168.x.x`、`2026/09/24 10:06`）
4. 右边点 **详情** → 展开后是结构化字段（动作、原状态、新状态、使用人、存放位置…）

> 顺手试试**故意失败**的操作：把一台已报废的设备的「状态操作」点一遍，或者去改一台不存在的设备。这些失败尝试也会留下审计记录，结果列标着「失败」—— 这才是审计最有价值的部分。

#### 2. 下载模板 → 填 10 台设备 → 导入 → 预览 10 条新增 → 确认入库

1. 顶部导航进 **批量导入**
2. 第 1 步点 **下载 Excel 模板** → 得到一个 `资产导入模板_2026-09-24.xlsx`，里面有三个工作表：`资产导入`（表头 + 2 行示例）/ `填写说明` / `列说明`
3. 打开它，把示例行删掉，填 10 行设备。**只有「IT资产编号」和「设备类型」是必填**，编号自己编（例如 `IT-2026-1001` 到 `IT-2026-1010`），类型写「主机」「显示器」这些已有名字
4. 回到页面，把文件拖进虚线框（或点一下选文件）→ 第 2 步选 **新增或更新**
5. 点 **预览导入结果** → 第 3 步出现 5 张统计卡：`总行数 10 / 将新增 10 / 将更新 0 / 无变化 0 / 错误 0`，下面表格逐行列出判定。**这一步还没写进数据库**
6. 点 **确认导入 10 条** → 第 4 步显示 `新增成功 10 条`，并引导你去审计日志
7. 回台账看一眼：顶部写着 `共 20 台设备`。审计页里多了一条 **批量导入**，内容是 `导入《你的文件名.xlsx》：新增 10 条，更新 0 条，跳过 0 条`

> 注意：**一次导入只留一条审计**。改了 10 台设备，时间线里是 10 条（设备视角），审计里是 1 条（操作者视角）—— 这才是审计该有的粒度。

#### 3. 同一份文件再导一次：选「仅新增」报重复，选「新增或更新」报无变化

1. 还在 **批量导入** 页，把刚才那份文件**再传一次**
2. 第 2 步选 **仅新增（报错）** → 预览 → `10 条全报错`，每行原因是
   `IT资产编号「IT-2026-1001」在系统里已存在（当前为「仅新增」模式，不会覆盖已有数据；如需更新请改用「新增或更新」）`，
   「确认导入」按钮变灰
3. 切到 **新增或更新** → 再点一次 **预览导入结果** → 这次是 `0 新增 / 0 更新 / 10 无变化 / 0 错误`

> 为什么一定要有「无变化」这一桶：少了它，第二遍导入会告诉你「更新了 10 条」——其实一个字节都没变。谎报一次，你以后就再也没法判断导入到底生效没有。

#### 4. 故意填错几行，预览能指出是哪一行、什么错

随便造一份有问题的小表（或者在模板里手动改坏几格），传上去预览。预期是**逐行**说清楚：

| Excel 行 | 你填的 | 预览会说什么 |
| --- | --- | --- |
| 第 3 行 | 编号和第 2 行写成一样 | `IT资产编号「IT-2026-3001」在文件里重复了（第 2 行已经用过）` |
| 第 4 行 | 设备类型那格空着 | `设备类型不能为空（漏填的话设备无法归类）` |
| 第 5 行 | 购入日期写「去年三月」 | `购入日期：日期格式无法识别：去年三月（请写成 2026-01-02 这样的格式）` |
| 第 6 行 | 编号那格空着 | `IT资产编号不能为空（它是判断新增还是更新的依据）` |
| 第 7 行 | 状态写「在修」 | `状态「在修」无法识别，只能是：在用、在库、维修中、已报废` |

注意第 2 行（没填错的那行）照样判定为「新增」。**有错的行会被跳过，正常的行照常导入** —— 不会因为一行错了就整份文件白干。

> 报的是 **Excel 里的真实行号**（第 1 行是表头，数据从第 2 行起）。给你一个内部索引等于没说，有行号你才能在 Excel 里直接定位到那一格。

#### 5. 导出当前筛选结果，文件能正常打开、列齐全

1. 回 **资产台账**，在关键字框里输入 `IT-2026-1`（筛出刚导进来的那 10 台）
2. 点右上角 **导出** → 弹窗里选 **当前筛选结果** + **Excel（.xlsx）** + 勾上 **附带配对的显示器信息** → 点 **导出**
3. 下载到 `IT资产台账_2026-09-24.xlsx`，打开看：
   - 表头 13 列 = 导入模板的 12 列 + `配对显示器`
   - 只有 10 行数据（就是你筛出来的这些，不是全部 20 行）
   - 第二个工作表 `说明` 里写着「这份文件可以直接导回」以及空值语义

> 想导全部就选「导出全部资产」，或者干脆点右上角的「重置」清掉筛选。

#### 6. 导出的文件改一改能再导回去

1. 打开刚才导出的那个 xlsx，把某台的「使用人」改个名字、把某台的「存放位置」改一下，保存
2. 回到 **批量导入** 页，把这个文件传上去，模式选 **新增或更新** → **预览导入结果**
3. 步骤 5 里那 10 台会被判定为「更新」，**并且逐行列出你具体改了哪个字段**（`使用人 张伟 → 李强`）
4. 确认导入 → 回台账，改动生效；每台设备的时间线里也多了一条对应的「信息变更」

**验收这一步的最省事做法：原封不动导回去。** 什么都不改直接上传，应该得到 `0 新增 / 0 更新 / 10 无变化 / 0 错误` —— 这就证明导出列和导入列**完全对齐**（同一份列定义）。如果列名对不上，这一步会立刻现原形。

#### 7. 审计日志能按条件筛选并导出

在 **审计日志** 页：

- **时间范围**：默认最近 7 天。点顶部「今日操作」卡片 → 立刻缩成今天
- **操作类型**：多选下拉，选项按「资产台账 / 主机显示器配对 / 盘点 / 导入导出 / 设备类型」分组。只选「批量导入」→ 列表只剩导入记录
- **结果**：选「失败」→ 只剩被拒掉的那些请求
- **操作人 / IP**：下拉里是库里出现过的值
- **关键字**：搜操作对象、操作内容、操作人、IP
- 点右上角 **导出当前筛选 ▾** → Excel / CSV。导出的表 8 列：`时间 / 操作人 / IP 地址 / 操作类型 / 操作对象 / 操作内容 / 结果 / 补充信息`
- 导完刷新一下，会多出一条「导出审计日志」的记录 —— 导出也是数据离开系统，也得留痕

**日志只读。** 页面上没有编辑、删除按钮，后端也没有对应接口（只有 3 个 GET）。要长期归档就用 `backup.bat` 备份整个数据库文件。

#### 8. Windows 脚本三件套

| 验收点 | 怎么做 |
| --- | --- |
| 双击 `start.bat` 能起来 | 会依次打印 `[1/3]` `[2/3]` `[3/3]` 三步：找到可用的 Python（**实测依赖齐全才采用**）→ 前端页面就绪 → 启动服务。**它不会自动装依赖** —— 缺什么会打印缺失清单和一行可直接复制粘贴的安装命令，装上再双击一次即可 |
| 启动后浏览器自动打开 | 服务起来约 5 秒后自动打开 `http://127.0.0.1:<端口>`。没开成的话手动点控制台里打印的那个地址 |
| 双击 `stop.bat` | 服务停止，控制台打印 `正在停止端口 8080 上的服务（PID xxxx）...` |
| 重复双击 `start.bat` | 不会起两个实例：检测到服务已经在跑，直接打开浏览器然后退出 |
| 手机连同一局域网能访问并扫码 | 见上面「局域网内其他设备怎么访问」 |
| 双击 `backup.bat` 生成带日期的备份 | `backups/` 下出现 `it_assets_20260924_101100.db`，控制台会打印它的大小和里面的设备台数 |

#### 9. 删掉数据库重启，应该是空库

1. 停掉服务（双击 `stop.bat`），删掉 `backend\data\it_assets.db`
2. 双击 `start.bat` → 控制台打印 **`当前为空库（设备类型 6 个，资产 0 台）`**
3. 打开页面 → 台账页显示 **共 0 台设备**，没有任何 `IT-2026-xxxx` 示例设备
4. 点「设备类型」→ 主机 / 笔记本 / 显示器 / 键盘 / 鼠标 / 打印机 六个**字典数据还在**（每个 0 台）
5. 想看演示数据：`python backend\seed.py` → 10 台示例设备 + 配对 + 履历回来
6. 想清空：`python backend\reset.py` → 先自动备份，再要你输入 `RESET`
   - 故意输错（比如打个 `reset` 之外的词、或者直接回车）→ 会中止，数据一条不动

## 数据说明

- 数据库文件：`backend/data/it_assets.db`，首次启动自动建表
- **启动时不写任何业务数据。** 只会初始化设备类型这类字典数据（6 种）—— 没有它就没法录资产，它是系统能跑的最小前提。所以删掉 `.db` 重启，得到的是一个真正的空库：设备类型在，一台设备都没有
- 演示数据（10 台示例设备 + 配对 + 初始履历）**要手动灌**：`python backend\seed.py`
- 「使用人」和「存放位置」没有做成独立字典表，筛选下拉的候选值直接从已有设备里现算 —— 所以填一个新的人名或位置，下次它就会出现在下拉里，不用先维护后台

### 谁负责数据初始化

| 时机 | 做什么 | 怎么触发 |
| --- | --- | --- |
| 每次启动 | 建表 + 轻量迁移 | 自动 |
| 每次启动 | 空库时建 6 个设备类型（字典数据） | 自动 |
| 每次启动 | **不碰任何资产数据** | — |
| 需要时 | 灌 10 台演示设备 + 推导出的配对 + 初始履历 | `python backend\seed.py` |
| 需要时 | 清空全部业务数据（保留表结构和字典） | `python backend\reset.py` |

**为什么演示数据不自动灌。** 两个原因：一是分不清「库里这些设备是我录的还是系统塞的」；二是误删数据库文件后重启会凭空"长"出十台假设备，跟真实数据混在一起，比没数据更糟。改成手动触发，灌不灌你自己说了算。

`seed.py` 只在表为空时才写，所以对着一个已经有真实数据的库跑它，不会追加资产、不会往已有履历里插东西。

### 两个维护命令

```bash
python backend\seed.py             # 灌演示数据
python backend\seed.py --check     # 只看各表现在有多少条，什么都不写

python backend\reset.py            # 自动备份 → 列出将删除的内容 → 输入 RESET 确认 → 清空
python backend\reset.py --check    # 只看会删掉什么，一个字都不写
python backend\reset.py --yes      # 跳过手动确认（给自动化脚本用）
```

`reset.py` 删的是资产 / 配对 / 履历 / 盘点 / 审计日志，**保留表结构和设备类型** —— 清完界面还能正常用，只是没有数据。它默认先自动备份一份到 `backups\`（唯一后悔药），再要你亲手输入 `RESET` 才会动手；输错了、没输入、或者 stdin 是空的，一律中止。

> 服务开着也能跑这两个命令（SQLite 单文件，不用停服务）。真遇到 `database is locked`，先跑 `stop.bat` 再试。

### 七张表

| 表 | 存什么 |
| --- | --- |
| `device_types` | 设备类型 + 类别（`host` / `display` / `other`，决定能不能参与配对） |
| `assets` | 设备台账 |
| `asset_relations` | 主机 ↔ 显示器的配对关系。解绑不删行，改成 `active = false` 并记下解绑人和时间，所以换绑轨迹留得住 |
| `asset_events` | 变更事件，每台设备一条时间线。录入 / 信息变更 / 状态流转 / 配对解绑 / 盘点标记都往这里写 |
| `inventory_tasks` | 盘点任务（范围、发起人、状态、结束时间） |
| `inventory_items` | 盘点任务里的每一台设备 + 盘点结果。带一份发起时的账面快照，之后账面被改过能看出「盘点时在哪」 |
| `audit_logs` | 操作审计：一次写操作一条，带操作人 / IP / 操作类型 / 对象 / 摘要 / 成功失败 / 结构化明细 |
| `schema_meta` | 一次性迁移的记账表（key/value）。就为了记住「某个迁移已经做过了」 |

`audit_logs` 刻意**不挂外键**（`target_id` 就是个裸数字），也不跟随级联删除 —— 资产被删掉了，「谁删的」这条记录还得在，不然审计就是自欺欺人。

### 三条工程红线

**1. 「改状态」和「记历史」必须在同一个事务里。**
所有变更都走 `services/events.py` 的 `record_event()`，它只 `add` 不 `commit`，由调用方连同资产改动一起提交。这样不会出现「状态改了但历史没记」或者反过来的半截数据。审计走的是同一条路：`record_audit()` 也只 `add`，业务回滚它就跟着回滚。

**2. 派生状态算出来，不落库。**
比如「这台主机挂了几台显示器」「盘点进度百分比」，都是查询时现算的，不存在表里。否则一份数据两处存，迟早对不上。

**3. 时间一律存本地时间。**
第一阶段有几处用了 `server_default=func.now()`，它在 SQLite 下编译成 `CURRENT_TIMESTAMP` —— **那是 UTC**。东八区的机器上，下午 5 点录入的设备在库里写着上午 9 点。第三阶段把这几处默认值全换成了 `datetime.now()`，并对老库做了一次整体平移（见下面「老库升级」）。审计最核心的就是「时间」，这个错不能留。

### 老库升级

老库不用删重建，`ensure_schema()` 在启动时做三件幂等的事：

1. **建缺的表**（新表 `audit_logs` / `schema_meta` 走 `create_all`）；
2. **给第二阶段之前的老库补 `device_types.category` 列**，补上后回填一次（按类型名猜：显示器 → 显示类，其他 → 其他）。只做一次，之后手动改过的类别不会被名字规则覆盖回去；
3. **把第三阶段之前被写成 UTC 的时间戳校正成本地时间。** 只平移确定被写成 UTC 的那几列（`created_at` / `updated_at`），**绝不动** `released_at` / `closed_at` / `checked_at` —— 那几个从一开始就是 `datetime.now()` 写的本地时间，往后挪 8 小时等于把好数据改坏。做完在 `schema_meta` 里记一笔，重复启动不会再执行。

启动日志会回显这次实际做了什么，例如：

```
数据库迁移：补 category 列 = 否；时间戳校正 = 37 行（时区偏移 480 分钟）
```

## 常见问题

**接口报错 / 页面空白？**
后端没起来。看启动窗口有没有报错，或者访问 `http://127.0.0.1:8080/api/health`，正常会返回 `{"status":"ok"}`。

**提示「前端尚未构建」？**
`frontend/dist` 不存在。执行 `start.bat --rebuild`，或手动 `cd frontend && npm install && npm run build`。

**端口被占用？**
默认用 8080。`start.bat` 会先检查端口，被占了就自动往后找（8081、8082…），并在控制台告诉你实际用的是哪个。
手动指定：`set IT_ASSET_PORT=18080` 再 `start.bat`，或 `python run.py --port 18080`。

> 注意：**8000 端口不要用**。这台机器上装了 C-Lodop 打印服务，它长期占着 8000 和 18000，访问 8000 会打开 C-Lodop 的页面而不是本系统。

**删除设备类型删不掉？**
该类型下还有设备。先把这些设备改成别的类型，再删。

**编号冲突？**
IT 资产编号是唯一的。留空让系统自动生成就不会冲突。

**点「+ 加显示器」说没有可选的？**
配对只认「类别 = 显示类」的设备类型。如果你新增了一个「一体机」类型但类别是「其他」，它不会出现在这里 —— 到「设备类型」里把它的类别改成显示类即可。

**配对 / 送修点了没反应，提示要填操作人？**
系统没有账号体系，所有写操作都要记「谁做的」。点右上角那个 👤 按钮填一次名字，存在你这台设备的浏览器里，以后就不用再填了。

**「已报废」的设备领用不了？**
这是故意的。报废设备只能「恢复入库」回到在库状态，然后才能领用。非法流转后端会拦下来并说明原因。

**盘点标记提示「设备不在这轮盘点的范围里」？**
这轮盘点发起时圈定的范围不含这台设备（比如你只盘了「显示器」类型）。想看结论的话，要么按同样的范围再发起一次，要么在发起时把范围放宽。

**时间线上一次改了一堆字段，怎么只显示一条？**
一次编辑产生的多个字段变化会合并成同一条「信息变更」事件，展开看得到 `品牌：空 → 联想` 这样的逐项明细。

**能像别的系统那样，用手机摄像头对着设备直接扫吗？**
不行，这是浏览器的硬限制：调摄像头必须 HTTPS 或 localhost，而本系统是局域网 `http://192.168.x.x`。所以改用系统相机 / 微信扫设备上已经贴好的二维码 —— 效果一样，而且微信里也能用。

**审计日志能删吗？**
不能，这是故意的。页面上没有编辑删除入口，后端也只有 3 个 GET 接口（没有 POST/PUT/DELETE）。要长期归档就用 `backup.bat` 备份整个数据库文件。真想物理清空，跑 `python backend\reset.py` —— 它是唯一会动审计日志的东西，本身带自动备份 + 输入 `RESET` 二次确认。

**审计里的「操作人」是空的怎么办？**
系统没有登录体系（这是明确的要求）。点右上角 👤 按钮填一次名字，存在你**这台设备的浏览器**里，之后所有操作都会带上。不同人用同一台电脑访问要各填一次；留空也能用，只是只剩 IP 能区分。

**导入之后设备没进去 / 数量对不上？**
看导入结果页的四个数字：`新增成功 / 更新成功 / 无变化跳过 / 导入失败`。如果「导入失败」大于 0，下面会逐条列出是哪一行、什么原因。有错的行会被跳过，**其余正常的行照常入库**，不会整份文件白干。

**导入时把某台设备的一个字段清空了怎么办？**
正常不会。更新已有设备时，**空单元格表示「保持原值不变」**，不是清空。只有你明确写了 `-`（或 `空` / `null`）才会把那格清掉。所以「拿一份只有两列的表刷使用人」是安全的，不会顺手抹掉品牌型号。

**导出再导回来，为什么显示「无变化」而不是「更新」？**
因为它真的没变。导出列和导入模板列是同一份定义，原样导回去本来就应该是零改动。这恰恰是列对齐的证明 —— 如果列名对不上，那些行会报「字段识别不了」而不是「无变化」。

**导入时设备类型写了个系统里没有的名字？**
默认会**自动创建**这个类型（按名字猜是主机类 / 显示类 / 其他）。不想让它自动建，把第 2 步的开关切到「报错」，那样类型名必须先建好，否则逐行报错。

**CSV 导入进去中文变乱码？**
系统导出的 CSV 带 BOM，没问题。如果是你自己在 Excel 里「另存为 CSV」，Excel 中文版默认存成 GBK —— 这个也认。再不行会退回 latin-1 兜底，保证不会因为编码直接崩掉。

**改了 `start.bat` 中文变成乱码？**
这几个 bat 必须存成 **ANSI / GBK 编码 + CRLF 换行**。存成 UTF-8 的话，Windows 控制台（代码页 936）读多字节内容会错位，不只是乱码，甚至可能执行错命令。

**我删了数据库，重启后怎么又长出一堆设备？**
以前会，现在不会了。启动时只建表 + 初始化设备类型，**不写任何资产**。删掉 `backend\data\it_assets.db` 重启，得到的是一个空库（设备类型 6 个、设备 0 台）。
要演示数据得自己跑 `python backend\seed.py`。这样就不会分不清「库里这些设备是我录的还是系统塞的」。

**启动后台账是空的，示例设备哪去了？**
同上 —— 演示数据不自动灌。`python backend\seed.py` 就有了。`python backend\seed.py --check` 可以只看每个表现在有多少条，不做任何写入。

**怎么把系统清空成一张白纸？**
`python backend\reset.py`。它会先自动备份一份到 `backups\`，列出将删除的内容，然后要你亲手输入 `RESET` 才动手。删掉的是资产 / 配对 / 履历 / 盘点 / 审计日志，**设备类型和表结构都留着** —— 清完界面还能正常用，只是没数据。
想先看看会删什么：`python backend\reset.py --check`（一个字都不写）。

**跑 `seed.py` 会不会把我自己的数据搞乱？**
不会。它每一步都只在对应表**完全为空**时才写。对着一个有真实数据的库跑它，不会追加资产、不会往已有履历里插东西。

**备份文件越攒越多？**
`backup.bat` 默认只保留最近 30 份，更早的自动清理。想留更多就手动跑：

```bash
python backend\backup_db.py --keep 365
```

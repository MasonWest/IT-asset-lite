# IT 资产管理系统

办公室 IT 设备的台账工具。**录入 → 扫码查详情 → 主机显示器配对 → 状态流转 → 盘点 → 批量导入导出 → 操作审计**，双击一个脚本就能起服务。

- 每台设备一个二维码，贴到机器上，手机扫一下就能看到这台机器的全部信息
- 显示器到底挂在哪台主机上，一张页面看清、一步改完
- 领用 / 归还 / 送修 / 报废都记进变更历史，每台设备一条时间线
- 一批新电脑到货？下载 Excel 模板填一遍导进去，导入前先给你看清楚要改什么
- 谁把哪台设备改成了什么，审计页一条条记着（时间 / IP / 操作人 / 对象 / 变更内容）
- 手机浏览器打开就能用，不需要装 App

## 现在有什么

| 能力 | 说明 |
| --- | --- |
| 资产台账 | 新增 / 编辑 / 删除 / 查看。字段：IT 资产编号、财务编码、设备类型、品牌、型号、序列号 SN、状态、使用人、存放位置、购入日期、保修到期日、备注 |
| 设备类型可自定义 | 预置主机、笔记本、显示器、键盘、鼠标、打印机，可自己加（服务器、交换机、平板…）并指定类别。每种类型在列表 / 详情 / 配对页都带自己的图标（电视 📺、一体机 🖳、家具 🪑…）；自己新建的类型按名字里的关键字自动配图标 |
| 筛选与视图 | 按类型 / 状态 / 使用人 / 位置筛选 + 关键字搜索。**类型 / 位置 / 使用人可多选** —— 一次勾几个，筛选框里以标签显示已选项（超一个折叠成 `+N`）；卡片 / 表格双视图；顶部状态卡片点一下就是筛选。**筛选条件和页码会写在地址栏上**：刷新不丢、能加书签、也可以把链接原样发给同事；点进某台设备的详情再返回，筛选原样保留 |
| 套装聚合展示 | 台账页的一个开关：打开后把「主机 + 它挂着的显示器」合并成一行看，列表立刻变短（实测 143 台 → 96 行）。表格视图里点行首的箭头能展开这套机子的显示器明细。**它只是换了个看法**：设备一台都没变，编号、状态、保修、使用人各自独立，配对关系也不动。**导出和打印标签永远按设备明细走**，不受这个开关影响 |
| 二维码 | 每台设备一张，内容就是它自己的详情页地址；可下载 PNG |
| 批量打印标签 | 左边可按**设备类型 + 存放位置**缩范围（补打某一台时不用在全部设备里翻），再调大小 / 每行个数 / 显示字段，直接调浏览器打印（A4 排版） |
| 主机 ↔ 显示器配对 | 一台主机可挂多台显示器；一台显示器同一时刻只能挂在一台主机上。支持绑定 / 换绑 / 解绑，**解绑不删记录**。给主机加显示器时**默认只列还没配出去的**（要看已挂机的点一下开关）；主机列表可「只看没配显示器的」 |
| 状态流转 | 在库 / 在用 / 维修中 / 已报废；操作有 领用 / 归还 / 送修 / 维修完成 / 报废 / 恢复入库。非法流转由服务端拦下（409）并给出人话原因 |
| 变更历史时间线 | 录入 / 信息变更 / 状态流转 / 配对解绑 / 盘点标记，每台设备一条倒序时间线 |
| 盘点任务 | 按类型 / 状态 / 使用人 / 位置 / 关键字圈定范围，发起时实时预览会盘到几台；逐台标记已盘 / 未盘 / 异常；差异清单 + 导出 xlsx / CSV |
| 扫码盘点 | 手机扫二维码落到详情页，顶部直接出现「标记已盘 / 异常」按钮 |
| 操作审计 | 每一次写操作留一条：时间、操作人、IP、操作类型、操作对象、变更内容、结果。**失败的尝试也记**。可按条件筛选、可导出；只读，不提供编辑删除 |
| 批量导入 | 支持 .xlsx / .csv；模板下载 → 拖入文件 → 预览（新增 / 更新 / 无变化 / 失败四桶 + 逐行问题）→ 确认入库。可选「仅新增」或「新增或更新」 |
| 批量导出 | 当前筛选或全部；可选附带配对的显示器信息；导出列与导入模板完全一致，改一改能直接导回来 |
| Windows 脚本 | `start.bat` / `stop.bat` / `backup.bat` / `dev.bat`，双击即用 |

## 快速开始

### 方式一：双击 `start.bat`（推荐）

脚本会依次做：检查是否已在运行 → 挑一个可用端口 → 找可用的 Python → 检查依赖 → 构建前端页面（首次）→ 启动服务 → 5 秒后自动打开浏览器。

**它用的是你电脑上已经装好的 Python，不会创建虚拟环境，也不会自动往你的 Python 里装东西。**

依赖只需要手动装一次：

```bat
python -m pip install -r backend\requirements.txt
```

装完以后，每次双击 `start.bat` 就只是「找 Python → 起服务」，几秒钟的事。如果提示缺依赖，脚本会告诉你缺哪几个包，并打印一行可以直接复制粘贴的命令，照做一次就行。

看到下面这些就说明起来了：

```
  电脑访问   http://127.0.0.1:8080
  手机扫码   见下面控制台里「手机扫码」那一行
```

想停止服务，**在这个窗口按 `Ctrl+C`**，或者**另外双击一次 `stop.bat`**。

#### 四个脚本的分工

| 脚本 | 干什么 | 什么时候用 |
| --- | --- | --- |
| `start.bat` | 找 Python → 检查依赖 → 构建前端 → 起服务 → 开浏览器 | 日常启动 |
| `stop.bat` | 按端口找到正在监听的 `python.exe` 并结束它 | 忘了服务在哪个窗口 / 窗口关了但进程还在 |
| `backup.bat` | 把数据库备份成 `backups/it_assets_年月日_时分秒.db` | 定期备份，或动数据之前先存一份 |
| `dev.bat` | 后端热重载 + 前端 Vite dev server | 改代码时 |

`stop.bat` 只结束 `python.exe`。如果那个端口被别的程序占着，它会告诉你「不是本系统，跳过」，不会误伤。

#### 启动脚本的几个细节

- **端口是自动挑的。** 从 8080 开始，被占用了就往后找 8081、8082…，并在控制台告诉你实际用的是哪个。不想让它自动挑：`set IT_ASSET_PORT=18080` 再运行。实际端口会写进 `.tmp/last-port.txt`，`stop.bat` 靠它定位。
- **重复双击 `start.bat` 不会起两个服务。** 它会先探一下上次用的端口，发现接口还在响应就直接帮你打开浏览器，然后退出。
- **脚本怎么找 Python：** 按 `py -3` → `python` → `python3` 的顺序逐个**实测** —— 先试着用它跑一次依赖自检，能起来且依赖齐全才采用。不是简单取 PATH 里第一个，因为电脑上可能装了好几个 Python。
- **想知道当前用的是哪个 Python、缺什么依赖：** 执行 `python backend\check_env.py`，它会打印解释器完整路径、每个依赖的版本、缺了哪几个、以及可直接复制的安装命令。
- **想重新构建前端：** `start.bat --rebuild`。
- **`start.bat` / `stop.bat` / `backup.bat` / `dev.bat` 都是 GBK 编码 + CRLF 换行的。** 改了这几个文件记得存成 ANSI/GBK —— 存成 UTF-8 中文会变乱码，甚至可能执行错命令。

### 方式二：手动启动

**后端**

```bash
pip install -r backend\requirements.txt    # 只需装一次
cd backend
python run.py                              # 默认 8080 端口
```

`run.py` 可以从任意目录执行。换端口：`python run.py --port 18080`，或设环境变量 `IT_ASSET_PORT=18080`。

> 想用虚拟环境做隔离当然也可以，自己建就行（`python -m venv .venv`）。只是脚本不会替你建。

**前端（只用开发模式时才需要）**

```bash
cd frontend
npm install
npm run build                     # 构建产物交给后端托管
```

开发时用 `dev.bat` 或 `npm run dev`，Vite 会把 `/api` 代理到 `http://127.0.0.1:8080`。

## 日常操作

### 备份与恢复

双击 `backup.bat`。它会打印出数据库文件和备份目录的完整路径，一眼能看清东西在哪：

```
数据库文件：E:\IT_snipe\backend\data\it_assets.db
备份目录  ：E:\IT_snipe\backups

[完成] 已生成备份：it_assets_20260924_101100.db
       大小 192.0 KB，包含 10 台设备
```

它走的是 SQLite 的**在线备份接口**，服务正在运行、有人正在录入也能拿到完整一致的数据（直接 copy 文件在写入时有概率拿到写了一半的页面）。备份完会做一次完整性校验，校验不过会删掉那个文件并报错 —— 不会给你留个 0 字节的「成功备份」。默认只保留最近 30 份，更早的自动清理。

命令行等价写法（想改保留份数时用这个）：

```bash
python backend\backup_db.py --keep 100
python backend\backup_db.py --list        # 只看不建
python backend\backup_db.py --out D:\bak  # 换目录
```

**恢复**：停掉服务，把 `backups\it_assets_xxxx.db` 复制成 `backend\data\it_assets.db`（覆盖），再启动。恢复前建议先把当前那份改个名留一手。

### 数据初始化：删库重启 = 空库

数据库文件在 `backend/data/it_assets.db`，首次启动自动建表。

**启动时不写任何业务数据。** 只会初始化设备类型这种字典数据（6 种）—— 没有它就没法录资产，它是系统能跑的最小前提。所以删掉 `.db` 重启，得到的是一个真正的空库：设备类型在，一台设备都没有。

| 时机 | 做什么 | 怎么触发 |
| --- | --- | --- |
| 每次启动 | 建表 + 轻量迁移 | 自动 |
| 每次启动 | 空库时建 6 个设备类型（字典数据） | 自动 |
| 每次启动 | **不碰任何资产数据** | — |
| 需要时 | 灌 10 台演示设备 + 配对 + 履历 | `python backend\seed.py` |
| 需要时 | 按编号规则批量补主机↔显示器配对 | `python backend\link_monitors.py` |
| 需要时 | 清空全部业务数据（保留表结构和字典） | `python backend\reset.py` |

**为什么演示数据不自动灌。** 一是分不清「库里这些设备是我录的还是系统塞的」；二是误删数据库文件后重启会凭空"长"出十台假设备，跟真实数据混在一起，比没数据更糟。改成手动触发，灌不灌你自己说了算。

### 三个维护命令

```bash
python backend\seed.py              # 灌演示数据
python backend\seed.py --check      # 只看各表现在有多少条，什么都不写

python backend\link_monitors.py                # 批量配对：只看计划，不写库
python backend\link_monitors.py --yes          # 先自动备份，再实际写入
python backend\link_monitors.py --suffix=_M    # 改后缀（默认 -M）

python backend\reset.py             # 自动备份 → 列出将删除的内容 → 输入 RESET 确认 → 清空
python backend\reset.py --check     # 只看会删掉什么，一个字都不写
python backend\reset.py --yes       # 跳过手动确认（给自动化脚本用）
python backend\reset.py --no-backup # 不先备份（不推荐）
```

三条命令都**幂等且不碰已有数据**：`seed.py` 只在对应表**完全为空**时才写，所以对着一个有真实数据的库跑它，不会追加资产、不会往已有履历里插东西；`link_monitors.py` 已经配好的会跳过，重跑第二遍不会重复绑定；`reset.py` 删的是资产 / 配对 / 履历 / 盘点 / 审计日志，**保留表结构和设备类型** —— 清完界面还能正常用，只是没有数据。

`reset.py` 默认先自动备份一份到 `backups\`（唯一后悔药），再要你亲手输入 `RESET` 才会动手；输错了、没输入、或者 stdin 是空的，一律中止。

**`link_monitors.py` 解决什么。** 批量导入的资产里，显示器编号常常是「对应主机编号 + `-M`」，比如主机 `B022-03-00001` 配的显示器叫 `B022-03-00001-M`。几十上百台一台上界面点「绑定」不现实，这条命令按命名规则一次性关联完。它的规矩：

- **默认只分析不写库**，必须加 `--yes` 才动手（和 `reset.py` 相反：那边默认要确认词，这边默认连确认都不给，直接干跑）；
- 落库前**自动备份**，备份失败就不动手；
- 写入走的是界面同一套代码（校验、状态机、变更履历、审计日志全都有），审计按「一次批量操作记一条」的口径留痕；
- **只做加法**：显示器已经挂在别的主机上时**跳过并列出来**，不擅自换绑 —— 换绑会抹掉它以前的归属，这种决定留给人做；
- 任何一条写失败，**整批回滚**。

> 服务开着也能跑这两个命令（SQLite 单文件，不用停服务）。真遇到 `database is locked`，先跑 `stop.bat` 再试。
> 想看启动时自动灌（做演示 / 截图）：设 `IT_ASSET_SEED_ON_STARTUP=1`，别长期开着。

### 可配置的环境变量

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `IT_ASSET_PORT` | `8080` | 服务端口 |
| `IT_ASSET_HOST` | `0.0.0.0` | 监听地址，改成 `127.0.0.1` 就只有本机能访问 |
| `IT_ASSET_PUBLIC_BASE_URL` | 自动探测 | 强制指定二维码里用的地址，例如 `http://192.168.1.23:8080` |
| `IT_ASSET_DATA_DIR` | `backend/data` | 数据库文件存放目录 |
| `IT_ASSET_BACKUP_DIR` | `backups` | 备份目录（`backup.bat` 和设置弹窗都读它） |
| `IT_ASSET_SEED_ON_STARTUP` | 关闭 | 设成 `1` 才在启动时自动灌演示数据（演示 / 截图用） |
| `IT_ASSET_SKIP_SEED` | 关闭 | 设成 `1` 则连设备类型字典也不自动建（只建表，全空） |
| `IT_ASSET_FRONTEND_DIST` | `frontend/dist` | 前端构建产物目录 |
| `IT_ASSET_TRUST_PROXY` | 关闭 | 设成 `1` 才信任 `X-Forwarded-For` 里的客户端 IP |
| `IT_ASSET_DATABASE_URL` | `sqlite:///…/it_assets.db` | 换数据库时用（PostgreSQL 等） |

## 局域网内其他设备怎么访问

服务默认监听 `0.0.0.0`，**同一局域网里的任何设备都能访问**，不需要额外配置。手机不用装 App，别的电脑也不用装。

**第一步，拿到电脑的局域网地址。** 启动服务时控制台会打印一行：

```
手机扫码 : http://192.168.1.23:8080
```

**第二步，在别的设备上打开它。**

- **手机**：连上同一个 Wi-Fi，浏览器地址栏输入这个地址。或者更省事 —— 打开某台设备的详情页，用手机相机 / 微信扫页面上的二维码，直接跳到那台设备的详情页。
- **另一台电脑**：浏览器输入同样的地址即可。

**第三步（只在打不开时才需要），放行防火墙。** Windows 默认会拦掉外部访问 8080 端口。用**管理员身份**打开 PowerShell 或 CMD，执行一次：

```bat
netsh advfirewall firewall add rule name="IT资产管理8080" dir=in action=allow protocol=TCP localport=8080
```

（端口如果被自动顺延到了 8081，把上面命令里的 8080 换成实际端口。）

### 扫不出来 / 打不开怎么办

**先查防火墙**（见上面第三步）。**再查 IP 对不对** —— 电脑上有 VPN、虚拟机（VMware/VirtualBox）、WSL 时，程序自动探测到的网卡地址可能是用不了的那个。在 CMD 里执行 `ipconfig`，找到你正在用的那个网卡的 IPv4 地址（一般是 `192.168.x.x` 或 `10.x.x.x`）。

然后点右上角 **⚙ 设置**，把「自定义扫码地址」填成 `http://192.168.x.x:8080`，保存。二维码会立刻按新地址重新生成。

**想改端口？** 三个办法任选一个：

```bat
set IT_ASSET_PORT=18080
start.bat                          :: 当前窗口临时生效
```

```bat
setx IT_ASSET_PORT 18080           :: 永久写进用户环境变量
```

或者直接 `python run.py --port 18080`。改了端口之后，二维码地址会自动跟着变，不用手动改设置。

其他可能：公司 Wi-Fi 开了「AP 隔离 / 客户端隔离」，同一 Wi-Fi 下设备也互相访问不了 —— 要么关掉隔离，要么用手机热点让电脑连上，再按热点网段填地址。

## 常见问题

**接口报错 / 页面空白？**
后端没起来。看启动窗口有没有报错，或访问 `http://127.0.0.1:8080/api/health`，正常会返回 `{"status":"ok"}`。

**提示「前端尚未构建」？**
`frontend/dist` 不存在。执行 `start.bat --rebuild`，或手动 `cd frontend && npm install && npm run build`。

**端口被占用？**
默认 8080，被占了 `start.bat` 会自动往后找并在控制台告诉你。手动指定：`set IT_ASSET_PORT=18080` 再 `start.bat`。

> 注意：**8000 端口不要用**。这台机器上装了 C-Lodop 打印服务，它长期占着 8000 和 18000。

**我删了数据库，重启后怎么又长出一堆设备？**
以前会，现在不会了。启动时只建表 + 初始化设备类型，**不写任何资产**。删掉 `backend\data\it_assets.db` 重启，得到的是空库（设备类型 6 个、设备 0 台）。要演示数据得自己跑 `python backend\seed.py`。

**启动后台账是空的，示例设备哪去了？**
同上 —— 演示数据不自动灌。`python backend\seed.py` 就有了；`--check` 可以只看各表条数、不做任何写入。

**怎么把系统清空成一张白纸？**
`python backend\reset.py`。先自动备份到 `backups\`，列出将删除的内容，然后要你亲手输入 `RESET` 才动手。设备类型和表结构都留着。想先看会删什么：加 `--check`（一个字都不写）。

**配对 / 送修点了没反应，提示要填操作人？**
系统没有账号体系，所有写操作都要记「谁做的」。点右上角 👤 按钮填一次名字，存在你这台设备的浏览器里，之后就不用再填了（留空也能用，只是只剩 IP 能区分）。

**「已报废」的设备领用不了？**
故意的。报废设备只能「恢复入库」回到在库状态，然后才能领用。非法流转后端会拦下并说明原因。

**点进设备详情，返回后台账的筛选没了？**
v1.1.2 起不会了。台账的筛选 / 页码 / 视图都写在地址栏上，详情页的「返回」会照着原样恢复。地址栏会因此变长（例如 `/?device_type_id=1,3&page=2`），这是正常的 —— 它就是当前列表的完整状态，可以直接收藏或发给同事。

**点「+ 加显示器」说没有可选的？**
配对只认「类别 = 显示类」的设备类型。如果新增了一个「一体机」类型但类别是「其他」，它不会出现在这里 —— 到「设备类型」里把类别改成显示类即可。

**配对管理里，主机怎么少了几台？**
被页面上方那个过滤开关挡住了。使用人填 `/`（或全角 `／`）是「这台不归谁」的写法 —— 公共大厅、资料室那类机器常这么写，它们多半没有显示器，却会把真正要配的机器淹掉（实测 19 台待配里占了 13 台），所以默认不显示。想看就把那个开关取消勾选。想让某台机器彻底回到列表里，到它的详情页把使用人改成真实姓名或留空即可。**显示器不受这条规则影响** —— 显示器就算写了 `/` 也照样列出来，因为它还得有人给它找主机去挂。

**盘点标记提示「设备不在这轮盘点的范围里」？**
这轮盘点发起时圈定的范围不含这台设备（比如你只盘了「显示器」类型）。按同样范围再发起一次，或发起时把范围放宽。

**导入时把某台设备的一个字段清空了怎么办？**
正常不会。更新已有设备时，**空单元格表示「保持原值不变」**，不是清空。只有你明确写了 `-`（或 `空` / `null`）才会把那格清掉。所以「拿一份只有两列的表刷使用人」是安全的，不会顺手抹掉品牌型号。

**导出再导回来，为什么显示「无变化」而不是「更新」？**
因为它真的没变。导出列和导入模板列是同一份定义，原样导回去本来就应该是零改动 —— 这恰恰是列对齐的证明。

**导入之后设备没进去 / 数量对不上？**
看导入结果页的四个数字：`新增成功 / 更新成功 / 无变化跳过 / 导入失败`。失败大于 0 时下面会逐条列出是哪一行、什么原因。**有错的行会被跳过，其余正常的行照常入库**，不会整份文件白干。

**CSV 导入进去中文变乱码？**
系统导出的 CSV 带 BOM，没问题。如果是你自己在 Excel 里「另存为 CSV」，中文版 Excel 默认存成 GBK —— 这个也认。再不行会退回 latin-1 兜底，保证不会因为编码直接崩掉。

**能像别的系统那样，用手机摄像头对着设备直接扫吗？**
不行，这是浏览器的硬限制：调摄像头必须 HTTPS 或 localhost，而本系统是局域网 `http://192.168.x.x`。所以改用系统相机 / 微信扫设备上已经贴好的二维码 —— 效果一样，而且微信里也能用。

**审计日志能删吗？**
不能，这是故意的。页面上没有编辑删除入口，后端只有 3 个 GET 接口。要长期归档就用 `backup.bat` 备份整个数据库文件。真想物理清空，跑 `python backend\reset.py`。

**备份文件越攒越多？**
`backup.bat` 默认只保留最近 30 份。想留更多：`python backend\backup_db.py --keep 365`。
